# Bilingual Documentation Guidelines

**English** · [简体中文](../i18n.md)

## Directory Convention

To avoid breaking existing links, Chinese source documents remain at their current paths and English translations are placed in matching `en/` directories:

```text
docs/
├── architecture.md              # Chinese source
├── en/
│   └── architecture.md          # English translation
└── zh-CN/
    └── README.md                # Chinese homepage

server/docs/
├── getting-started/
│   └── development.md           # Chinese source
└── en/
    └── getting-started/
        └── development.md       # English translation
```

Keep images and other shared resources in `docs/assets`; do not duplicate them by language. Historical documents may remain Chinese-only, but new or updated frequently used documents should include an English translation.

## Translation Priorities

1. README files, quick starts, installation and deployment, configuration, client integration, security, and contributing guides.
2. Architecture, permissions, HTTP APIs, MCP, development guidelines, and operations manuals.
3. Historical designs, plans, discussions, and customer-specific material, which can be translated as needed or explicitly marked Chinese-only.

## Document Requirements

- Provide language switcher links at the top of every bilingual document.
- Preserve the meaning of commands, environment variables, API paths, field names, error codes, version numbers, and code examples. Do not translate technical identifiers.
- Manually review permissions, security, migrations, and deployment content; do not rely solely on machine translation.
- Both languages must describe the same current capabilities, limitations, and warnings. Planned capabilities must be explicitly marked as such.
- Adjust links for each document's directory and reference shared images whenever possible.
- Update the English translation when changing the Chinese source. If synchronization is not possible, list the outstanding translation work in the PR.

## Verification

The bilingual check covers the first batch of required documents, relative links, images, and code fences:

```bash
python3 scripts/docs_i18n_check.py
```

The script validates document structure and links only. It cannot determine translation accuracy; technical content still requires human review.
