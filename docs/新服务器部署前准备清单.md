# Clawee 新服务器部署前准备清单

本文用于新建 Linux Gateway 环境。以下地址、账号和目录均为示例；实际部署配置和凭据保存在仓库外的 `CLAWEE_OPS_DIR` 中。

## 1. 确认环境

记录服务器架构、SSH 地址、部署账号、服务目录、Gateway 访问域名及 PostgreSQL 连接方式。例如：

| 项目 | 示例 |
| --- | --- |
| SSH | `deploy@192.0.2.10`（文档示例地址，须替换） |
| 部署目录 | `/opt/clawee` |
| Gateway | `https://gateway.example.com` |
| systemd 服务 | `claw-gateway.service` |

检查系统架构、时间同步、磁盘容量与网络连通性：

```bash
hostnamectl
uname -m
timedatectl
df -h
```

## 2. 准备账号与依赖

配置部署账号的 SSH 公钥，验证 `ssh -o BatchMode=yes deploy@192.0.2.10 'id -un'` 可以成功。根据发布脚本实际执行的服务安装、systemd 管理和容器操作配置 sudo 权限，不沿用其他环境的账号或授权规则。

如使用仓库提供的 PostgreSQL Compose 配置，安装 Docker Engine 和 Compose Plugin，并检查 `docker info`、`docker compose version`。如使用外部 PostgreSQL，在目标配置中设置 `requires_docker: false`，确认数据库可达且版本满足项目要求。

## 3. 准备私有配置

```text
/opt/clawee-ops/
├── configs/
│   └── config.demo.yaml
└── deploy/
    └── servers.yaml
```

从 `server/configs/config.example.yaml` 复制配置到上述私有目录，设置数据库 URL、JWT 签名密钥、Agent Token 加密密钥与实际访问地址。按需启用钉钉、知识库等集成。配置文件权限设为 `0600`，不要提交到 Git。

部署目标示例：

```yaml
servers:
  demo:
    ssh: deploy@192.0.2.10
    deploy_dir: /opt/clawee
    arch: linux-amd64
    service: claw-gateway.service
    config: configs/config.demo.yaml
    requires_docker: true
```

目标字段以 [Gateway 生产部署指南](../server/docs/deployment/production.md) 和仓库部署脚本为准。

## 4. 检查网络与数据库

- PostgreSQL 仅绑定回环地址或受控私网，使用独立账号和强密码。
- 防火墙仅允许必要来源访问 Gateway；公网使用 HTTPS 反向代理。
- HTTPS 部署同步配置 `mcp.public_base_url`、OAuth 回调和安全 Cookie。
- 检查是否存在旧容器、数据卷或数据库；已有数据必须先确认归属、备份与恢复路径，不能直接覆盖。
- 开源版本不包含客户专属员工目录和组织同步。不得覆盖正在使用专属适配的实例；启动时如检测到遗留组织数据会拒绝启动，且不会自动清除权限。

## 5. 发布与验收

按 [运维部署指南](operations/operations-guide.md) 完成本地验证、打包、迁移和部署。目标选择示例：

```bash
CLAWEE_OPS_DIR=/opt/clawee-ops server/scripts/deploy-release.sh demo
```

执行前核对目标、配置来源、停机窗口及备份。上线后验证健康检查、账号登录、权限、MCP 调用、知识库和共享文件等已配置能力；按需验证钉钉登录与审批。服务端集成测试始终使用独立测试数据库。
