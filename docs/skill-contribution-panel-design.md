# Skill 贡献面板方案设计

> 日期：2026-10-13。
> 状态：业务方向已确认；本文定义首版开发范围与验收依据，不表示功能已经上线。
> 定位：Clawee 客户端工作区中的人事数据工作面板，仅提供 Skill 上传、审核评分数据、对话查询与导出。

## 1. 已确认的业务边界

1. 奖励参考对象为一个 Skill 的首次审核通过，版本更新、重审和再次发布不重复计入；贡献默认归首次通过版本的认证上传人，不做多人奖励分配。
2. 上传统计按上传时间归属周期，首次通过名单按首次审核通过时间归属周期。
3. 人事手工处理奖励，Clawee 只提供数据，不计算奖励金额、不执行发奖、不登记已发奖、不判断某条贡献是否已经得到奖励。
4. 评分条件由人事查询时指定，不内置奖励门槛。符合查询条件不等于应当发奖，历史名单可以重复导出。
5. 首版按 `skill_id` 判断是否为同一个 Skill，不做同名或相似内容判重；删除后以新 ID 重建的情况由人事复核，不承诺防止重复申领奖励。

不做通用看板搭建、复杂图表、奖励审批、财务对接、员工绩效评分、使用次数评价或节省工时估算。首版不改变现有 Skill 上传、审核与发布流程。

## 2. 首版页面与工作流程

> 入口已按 [Skill 贡献入口归入工作台方案设计](skill-contributions-workbench-design.md) 调整到工作台「数据洞察」，保留独立路由、贡献专用会话及权限检查。模型门禁和侧栏例外以该方案为准。

客户端通过「工作台 → 数据洞察 → Skill 贡献」进入，侧栏不再提供独立贡献入口；路由仍为 `#/skill-contributions`，页面和授权提示均提供「返回工作台」。贡献页保留侧栏并高亮工作台，不要求选择本地项目。由共享 Web 实现，桌面端和浏览器端共用。已登录且 daemon 企业接口可用时，模型未就绪仍可进入目录、查询、查看详情和直接导出；贡献对话继续受模型门禁控制。

页面包含三个区域：

| 区域 | 首版内容 |
| --- | --- |
| 概览 | 上传数、首次通过 Skill 数、贡献人数、首次通过 Skill 的平均分 |
| 数据表格 | 「上传明细」「首次通过」「员工汇总」三个视图，筛选、分页、详情与导出 |
| 对话区 | 复用现有会话与 Run 执行链路，查询、解释口径、生成导出入口 |

默认周期为本月，支持上月与自定义日期。周期和员工筛选作用于整个面板；状态与最低总分只作用于支持这些条件的表格，不能悄悄改变概览口径。部门仅在既有可信账号资料可读取时提供；没有部门数据时不展示部门筛选，不为此新增组织同步。

详情使用抽屉展示对应审核的四维评分、每位审核人的评分与意见。首版不在此修改评分或处理审核。概览不受表格分页影响，页面不做员工排行榜。

对话默认继承当前周期、员工和当前表格视图；用户明确指定的条件覆盖默认条件。对话自行改变查询条件时，显示实际查询条件，不自动修改页面筛选。较窄窗口通过切换数据与对话视图保持同一会话，不另建聊天系统。

典型操作：打开面板，查看本月概览；询问「本月首次通过、总分不低于 16 分的 Skill 有哪些」；查看结果和筛选条件；导出名单；由人事在现有台账中核对并发奖。

## 3. 数据来源与统计口径

### 3.1 复用的现有能力

| 能力 | 仓库位置 | 使用方式 |
| --- | --- | --- |
| 上传事实 | `server/db/migrations/00058_employee_ai_activity_facts.sql`、`server/internal/skillhub/postgres_store.go` | 已有成功上传事务事实，不重复建设上传采集链路 |
| Skill、版本和上传人 | `server/internal/skillhub/` | 关联名称、版本、上传人和当前状态 |
| 人工审核评分 | `server/internal/skillhub/manual_scores.go`、`local_approval_postgres.go` | 沿用四维评分及审核完成条件 |
| 外部审核结果 | `server/internal/skillhub/external_approval_postgres.go` | 提供正式审核通过事实；没有人工四维分数则保持缺失 |
| 数据视图授权 | `server/internal/dataaccess/`、`server/internal/server/activity_http.go` | 注册独立视图，复用账号与角色授权 |
| 受控 MCP 查询 | `server/internal/agentactivitymcp/`、`server/internal/mcpgateway/` | 参考既有内置数据工具模式，不另建 Agent 服务 |
| 客户端导航与企业读取 | `client/apps/web/src/app/routes.ts`、`features/shell/ClaweeSidebar.tsx`、`client/apps/daemon/src/enterprise/` | 复用路由、登录会话和 daemon 到 Gateway 的访问边界 |

`docs/skill-usage-and-contribution-design.md` 是相关背景，不能把其中所有规划内容当作已上线能力。本面板不接入 Skill 使用证据或任务正文。

### 3.2 三种数据视图

| 视图 | 一行的单位 | 时间依据 | 数据来源 |
| --- | --- | --- | --- |
| 上传明细 | 一次成功上传的版本 | 上传事实 `occurred_at` | 上传事实左关联版本与审核信息 |
| 首次通过 | 一个 Skill 的首次正式审核通过 | 固定的 `first_approved_at` | 第 4 节首次通过记录 |
| 员工汇总 | 一个认证上传员工 | 上传与首次通过分别使用自己的时间依据 | 服务端按员工 ID 聚合前两类数据 |

上传仅统计 `actor_kind=user`、`origin IN (app_upload, admin_upload)` 的 `skill.created` 和 `skill.version_uploaded`，按 `(source_system, source_event_key)` 去重。新增与更新均属于上传，失败上传、下载安装到本地和 `source_sync` 不计入。

管理员代传默认归实际认证操作人，不从文件作者、备注或 AI 文本推断员工身份；明细带出上传来源，供人事识别代传情况。员工用稳定账号 ID 归组，同名员工不能合并。

正式审核指配置审核人的本地审核全部通过，或外部审核明确通过。自动同步、无审核配置的直接发布不作为正式审核通过。发布动作、AI 推荐通过和部分审核人同意均不等于审核最终通过。

上传明细展示当前审核状态与当前可用评分；首次通过视图展示首次通过时的评分快照。两种视图明确区分，后续更新的高分不能替换首次通过时的分数。

上传事实对应版本被删除后，仍保留上传计数与可用身份、名称，明细标记「版本已删除」，审核与评分字段为空，不通过内连接丢掉该次上传。缺失历史上传事实不从当前版本列表猜补，响应注明数据覆盖起点和历史限制。

### 3.3 指标定义

| 指标 | 确定性计算规则 |
| --- | --- |
| 上传数 | 周期内符合上述口径的去重上传事实数 |
| 首次通过 Skill 数 | 周期内首次正式通过且历史依据可确认的 Skill 数；每个 `skill_id` 最多一条 |
| 贡献人数 | 周期内上传员工与首次通过版本上传员工的并集人数 |
| 平均分 | 周期内首次通过且四维人工评分完整的 Skill 总分平均值，注明有效评分条数 |

四个维度为场景价值、结果有效性、使用便利性、复用价值，每项 1–5 分。沿用现有汇总：先对审核人的每个维度求平均，再将四维平均值相加，总分最高 20 分，不将多人评分累加成更高总分。

AI 建议分不参与统计。外部审核、旧数据或不完整评分显示「未评分」，不得补零或补 AI 分；最低分筛选排除未评分记录。服务端使用未取展示舍入的分数比较阈值，页面与文件可保留两位小数；没有有效分数时平均分为 `null`。

日期参数为自然日，开始日与结束日均包含，服务端转换为 `[开始日零点, 结束日次日零点)`。沿用既有服务端业务时区，没有可复用配置时首版固定 `Asia/Shanghai`，响应与导出注明实际时区；不按各客户端电脑时区计算月份。

## 4. 最小必要的首次通过记录

现有审核状态可能因配置调整、空间移动或重审被重置，`reviewed_at` 也可能被覆盖。因此不能只查询当前版本状态或对当前 `reviewed_at` 求最小值来判断首次通过，否则同一 Skill 可能跨月重复进入首次通过名单。

增加一张小型业务记录表，建议名为 `skill_first_approvals`，每个 Skill 一条。它记录审核事实，不是奖励台账，不添加奖励金额或发奖状态。

最小字段包括：`skill_id`（唯一键）、首次通过版本 ID 与版本号、上传员工 ID 与展示名、Skill 名称、审核时空间 ID、审核来源与关联审核 ID、`first_approved_at`、评分标准版本、四维汇总分和总分、审核人评分及意见快照。姓名和名称快照只用于历史辨识，不替代账号 ID。

写入约束：

1. 在本地最终审核通过或外部最终通过的同一事务内写入，使用 Skill 级锁与唯一约束保证并发不同版本只记录一次；重复回调、重审与更新不能覆盖记录。
2. 保留对应首次审核的评分和意见，不另建评分算法。没有评分则记录空值，不阻止正式通过事实写入。
3. 后续拒绝、配置调整、移空间或删除版本不改变历史首次通过；记录不能级联删除。当前实体已不可用时在名单中标记，供人事复核，不把历史通过解释为当前仍可使用。
4. 新增表和索引使用迁移；内存 Store 与 PostgreSQL Store 保持同一语义，不依赖手工修改运行库。

历史数据按保守规则处理：开发时先核实可保留的本地与外部审核历史；只有能够确认首次通过时间、版本与上传人的记录才能回填。只有当前通过状态、历史不完整或已清理的旧 Skill 标记「历史首次通过无法确认」，不计入可确认首次通过数，也不因上线后的更新通过而当作新贡献。

上线时记录历史覆盖边界，服务端依据 Skill 创建时间区分旧 Skill 与上线后新 Skill；「没有首次通过记录」不能统一解释为「从未通过」。历史不确定记录保留在上传查询和待核对明细中，不能无提示地从报表消失。首版不承诺恢复已丢失历史，也不建设通用事件溯源系统。

## 5. 服务端与客户端实现边界

```text
客户端贡献页面 -> daemon 企业接口 -> Gateway 贡献查询服务 -> 现有事实与首次通过记录
面板对话 -> 现有 Runtime / 企业 MCP -> 同一个贡献查询服务
页面或对话导出入口 -> daemon 认证下载 -> 同一个贡献导出服务
```

统计、身份归属、筛选、排序和导出均由 Gateway 确定性执行。daemon 负责现有企业认证、转发与下载，Web 负责展示，不直接连接数据库，也不在客户端长期复制企业贡献数据库。对话及下载文件沿用现有本地会话与文件边界。

建议在 `server/internal/skillhub/` 内新增贡献查询与首次通过记录实现，在现有 `server/internal/server/` 中挂载应用接口；MCP 薄适配层参考 `agentactivitymcp`，不复制查询逻辑。客户端新增 `features/skill-contributions/` 页面、企业 service 与 daemon manager/routes；共享请求响应契约放入 `client/packages/protocol`。不修改 Electron Bridge，除非复用下载实现确实要求原生能力。

### 5.1 最小接口契约

以下为新增接口建议，沿用现有响应封装与错误约定，不代表已有接口：

| 接口 | 作用 |
| --- | --- |
| `GET /api/v1/app/skill-contributions/summary` | 周期概览，只接收周期与员工、可用部门条件 |
| `GET /api/v1/app/skill-contributions/records` | 三种视图的筛选、分页与员工汇总 |
| `GET /api/v1/app/skill-contributions/detail` | 按版本 ID 或首次通过 Skill ID 查看对应审核详情 |
| `POST /api/v1/app/skill-contributions/export` | 同条件导出 CSV 文件，不保存发奖或导出业务台账 |

列表与导出共用请求模型：`start_date`、`end_date`、`report`（`uploads`、`first_approvals`、`employees`）、可选 `employee_id`、可用时的 `department_id`，以及适用视图的 `status`、`min_total_score`。列表另有分页参数。未知条件或不适用的条件返回参数错误，不能静默忽略。

列表默认每页 50 条，最大 100 条；上传和首次通过按对应时间倒序、唯一 ID 作为次排序，员工汇总按员工 ID 稳定排序。首版不增加任意排序表达式。汇总必须基于全量条件，不对当前页面求和。

响应至少包含规范化后的 `query`、`timezone`、`generated_at`、数据覆盖说明；列表另有 `items`、`total` 与分页信息。明细身份使用 `employee_id`，记录携带 `skill_id`、`version_id` 与可用审核 ID，便于人事对账；不同报表缺失或不适用的字段用 `null` 表达，不填伪造值。

员工汇总至少返回上传数、首次通过数、有效评分条数和平均分。最低分或审核状态筛选只支持明细视图；查询员工汇总需要分数条件时，先明确改为「筛选首次通过记录后按员工汇总」，首版未支持该组合则明确告知，不让模型自行算出正式汇总。

### 5.2 权限

新增独立数据视图 `skill_contributions`，复用现有账号、角色和 `data_view/read` 授权，不默认赋予全体员工，也不沿用 Agent 动态权限自动放行。

首版该授权代表当前企业内全体员工的贡献元数据读取，包括评分与审核意见；这是人事级授权，不因某个 Skill 空间可读而自动获得，也不授予 Skill 包、文件正文或上传权限。不新增部门级行权限，部门筛选不是授权边界。管理台仅补视图枚举与授权选项，不建设新管理页面。

视图发现、HTTP 查询、详情、MCP 调用与导出都检查该权限。数据查看权限默认包含 Agent 查询与导出；对应两个内置贡献工具不再要求独立 MCP Tool 授权，但保留既有账户与 Agent 身份校验，以服务端认证调用人判断，不能使用模型传入的用户 ID 授权。账号切换或授权撤销后清理面板结果和下载描述，重新访问返回 401/403；不保证撤回用户已下载的文件。具体开发与验收依据见 [数据统一授权与工作流结果共享方案](workflow-shared-files-and-data-authorization-design.md)。

## 6. 对话查询与导出

### 6.1 对话查询

首版只提供两个贡献工具：

| 工具建议名 | 用途 |
| --- | --- |
| `skill_contributions_query` | 选择概览、三种列表或详情，返回真实结构化数据、实际条件、口径与覆盖说明 |
| `skill_contributions_export` | 校验导出条件，返回受控下载描述，客户端呈现下载按钮 |

工具通过现有企业 MCP 目录与门禁注册。工具查询能力不多于页面，不提供 SQL、任意字段公式、数据库凭据或任意文件写入。

模型只负责把自然语言转成受支持的参数并解释查询结果，不自行补齐缺失数据、不按截断列表生成全量员工汇总，也不把页面的当前评分当成首次通过评分。工具结果带完整口径供模型解释，首版不增加独立口径工具。

「本月首次通过」可以直接查询；「高分 Skill」缺少分数门槛时先问用户；员工姓名重名时让用户确认账号。无权限、无数据、历史无法确认、模型不可用和不支持的统计分别说明；不支持的需求不能包装成已完成。部门数据不可用时不猜测。

### 6.2 导出

首版只提供 UTF-8 BOM 的 CSV，使用 Go 标准库 `encoding/csv`，可由 Excel 打开，不为此引入 XLSX 库、后台导出队列或云文件存储。

页面和对话共用认证下载流程。MCP 导出返回白名单类型与规范化条件，不返回 Token、任意 URL 或整份 CSV 文本；Web 将受控描述转换为下载动作，通过 daemon 调用 Gateway 导出接口，再次校验当前登录身份与权限。下载地址由应用固定构造，不能让模型指定目标地址。对话发起导出后可直接显示「下载 CSV」按钮，不要求人事跳出面板。

导出全部符合条件的记录，不限于当前页。首版上限 10,000 行，超过时明确要求缩小周期或范围，不能截断后称为完整导出。下载描述不冻结数据；实际文件在点击下载时查询，文件生成时间是本次下载时间，不承诺与之前聊天查询构成同一数据快照。

按报表输出中文列名，包含员工 ID 与姓名、Skill 与版本标识、适用的上传时间或首次通过时间、来源、审核状态、四维分数、总分和必要审核意见；员工汇总输出对应统计字段。每行同时带统计起止日、时区、生成时间与历史确认状态；无结果导出只有表头，并在界面提示无匹配记录。

对名称、意见等文本执行 CSV 公式注入防护，不能让以公式触发字符开头的用户文本被 Excel 执行；数值列保持数值语义。沿用现有审计记录调用人、操作类型、条件、时间与行数，不记录完整导出正文；不新增导出记录页面。

## 7. 页面状态与体验约束

使用客户端现有 CSS、设计令牌、表格与 Lucide 图标，不引入 Tailwind 或 shadcn/ui。概览和表格采用紧凑布局，不做营销式大标题、复杂图表或卡片嵌套。

未登录、无授权时不展示有效业务入口；直达路由仍做权限检查。数据加载、空结果、服务异常、历史覆盖不完整和下载失败分别有明确状态，异常不能显示为零。数据接口可用但模型不可用时，保留页面筛选和直接导出能力。

查询结果使用生成时间和简短覆盖提示；详细统计定义由详情或对话按需提供，不在页面堆叠功能说明。对话工具调用加载与导出按钮有稳定尺寸和明确错误状态，窄窗口与桌面窗口均不得遮挡主要操作。

## 8. 开发顺序与交付检查

1. **数据口径与首次通过记录** -> 验证：隔离测试数据库覆盖多人最终通过、外部回调、并发与幂等、重审、移空间和删除；核实历史可恢复范围。
2. **Gateway 查询、导出与授权** -> 验证：三种视图与概览对账，跨月与时区边界，缺分、同名账号、全量分页与导出权限一致。
3. **daemon 协议与客户端页面** -> 验证：当前企业会话转发、导航可见性、筛选详情、页面导出与窄窗口状态。
4. **对话工具接入** -> 验证：结构化真实查询、条件澄清、受控下载、模型不可用回退，不支持条件明确失败。
5. **集成验收** -> 验证：客户端相关测试、类型检查及根目录 `pnpm desktop:preflight:local`；服务端集成测试只使用隔离库。

完成客户端可执行代码后必须通过本地预检再宣称具备发布条件。本任务不自动触发正式发布，不操作生产数据；运行配置沿用仓库外 `CLAWEE_OPS_DIR` 或环境变量。

## 9. 首版验收标准

| 场景 | 必须得到的结果 |
| --- | --- |
| 人事查看面板 | 授权账号可在工作区进入；未授权账号页面、工具、详情和下载都不可读取 |
| 首次通过去重 | 一月通过后，二月版本更新、重审或再次发布不再成为二月首次通过贡献 |
| 上传与通过跨月 | 一月上传、二月通过分别计入对应月份；贡献归首次通过版本上传人 |
| 评分一致性 | 多审核人使用现有四维平均汇总，满分 20；AI 分、缺失分不混入人工平均 |
| 外部审核与免审 | 外部正式通过可记录首次通过但分数为空；免审直接发布和自动同步不冒充正式审核 |
| 历史与删除 | 无法确认的旧 Skill 不冒充首次通过；版本删除后上传事实与首次通过事实不重复、不丢失 |
| 真实全量数据 | 明细超过一页时概览与员工汇总仍为全量；CSV 与同条件服务端查询一致 |
| 查询与导出 | 对话可按周期、员工、状态及分数查询；CSV 有身份、统计条件与生成时间，公式文本不会执行 |
| 条件与异常 | 重名、含糊门槛、无权限、服务错误和不支持的统计不被模型猜补；超过导出上限不静默截断 |
| 奖励边界 | 无金额计算、发奖动作、已奖励状态或奖励台账；导出名单只作为人事参考 |

首版交付物为贡献查询与首次通过记录、CSV 导出、数据视图授权、客户端面板与两个对话工具。部门数据、历史恢复受既有可信数据限制，不为补齐这些内容扩展首版为组织平台或历史修复项目。
