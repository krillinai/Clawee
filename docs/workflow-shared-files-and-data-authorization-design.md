# 数据统一授权与工作流结果共享方案

> 日期：2026-10-13。
> 状态：业务方向已确认；本文作为首版开发与验收依据，不表示功能已实现。
> 原则：复用现有数据权限、工作流、共享网盘与存储能力，不新增权限系统、存储平台或后台任务队列。

## 1. 已确认的方向

1. “Skill 上传与评分数据”的查看权限，默认包含页面查看、Agent 查询和导出，不再单独授权对应 MCP 工具。
2. 每个工作流模板自动创建并绑定一个共享空间；每次执行使用空间下的独立目录，不为实例创建空间。
3. 实例发起人、所有节点执行账户和审批账户自动加入模板空间，默认共享全部节点结果。
4. 空间成员可以访问该模板所有历史及后续实例的文件。目录只用于整理，不是权限边界。
5. 只归档正式提交的结果与明确选择的附件；文件上传成功后才能推进工作流。

本期不做目录级权限、节点间文件隔离、在线协同编辑、跨模板共享、成员自动退出、文件自动清理或保存期限配置。不改变现有评分口径、审核规则和工作流调度方式。

## 2. 数据权限统一

### 2.1 唯一授权依据

沿用 `data_view / skill_contributions / read`，不增加新的授权记录或复选框。

| 入口 | 授权规则 |
| --- | --- |
| 页面概览、列表、详情与 CSV 下载 | 检查当前账户的数据查看权限 |
| `skill_contributions_query`、`skill_contributions_export` | 检查同一数据查看权限，不要求独立 MCP Tool 授权 |
| 其他 MCP 工具 | 保持现有规则，不扩大本次调整范围 |

实现要求：

- 以服务端认证账户判断权限，禁止信任模型传入的用户 ID。
- MCP 工具目录授权状态、聚合与单上游工具发现、实际调用及确认后的执行，使用一致的判定；不要只修改工具展示。
- 只对内置 `skill-contributions` 上游的上述两个工具采用数据权限规则，按真实上游与工具标识匹配，不能仅按名称放行其他上游。
- 保留账户与 Agent 状态、身份归属、Token、上游及能力停用、参数校验和现有审计。
- 查询数据权限出错时拒绝访问；旧 MCP 授权不能作为兜底放行依据。
- 撤销数据权限后，即使客户端缓存了工具目录，后续调用与实际下载仍被拒绝；客户端清理已展示的数据与下载描述。

不在数据授权时同步创建 MCP 授权。旧工具授权记录可以保留，但对这两个工具不再参与判定；管理台对应工具标明“随数据权限生效”，不再提供独立授权编辑入口。已持有数据权限的账户直接生效，无需重新授权。

该权限仍只提供贡献元数据、评分与审核意见，不授予 Skill 包、源码、上传或修改评分权限，也不自动授予任意共享空间权限。

## 3. 模板空间与实例目录

### 3.1 空间生命周期

- 新建模板时自动创建共享空间，并保存 `shared_space_id`；创建人与空间初始权限沿用现有规则。
- 保存已有模板时复用绑定空间，不因改名、修订或启停重建空间。空间名称包含模板 ID，避免同名模板冲突；无需同步模板与空间改名。
- 旧模板在首次保存或发起新实例时补建空间。并发请求锁定模板记录，保证只创建一次。
- 模板创建与空间绑定使用同一数据库事务；空间成员也写入现有 `data_resource_grants`，不要另建成员表。
- 停用模板、结束或终止实例均保留空间与文件。本期不新增模板或空间删除流程。

### 3.2 文件组织与存储

实际逻辑路径使用稳定 ID，不依赖可能改名或包含特殊字符的节点标题：

```text
模板共享空间
└── instances/<instance_id>/
    ├── nodes/<node_id>/<submission_id>/result.md
    ├── nodes/<node_id>/<submission_id>/result.json
    └── nodes/<node_id>/<submission_id>/attachments/<文件名>
```

`submission_id` 使用已有节点提交幂等键的稳定摘要，不额外建设版本系统。同一路径重复上传时，大小与摘要一致才复用，否则返回冲突，不覆盖原文件。不同节点、候选账户的不同提交使用不同路径。

复用 `shared_files.logical_path` 表达目录，不增加目录表或空目录对象。实例创建后即返回目录前缀，网盘文件写入后自然形成目录视图；显示名称可用执行日期和节点标题辅助识别。

文件内容沿用共享网盘当前启用的服务器持久化磁盘或 OSS；元数据与工作流关联存入 PostgreSQL。磁盘模式必须挂载持久化目录，数据库与文件分别纳入现有备份，不使用容器临时目录。客户端本地文件不是跨账户共享的正式来源。

## 4. 成员与权限

### 4.1 自动加入

在实例启动事务内，复用现有角色解析结果与 `workflow_instance_participants` 名单，加入发起人及所有节点的全部有效候选账户，包括审批账户，而不是只加入最终处理人。

- 不在保存模板时额外解析、同步角色成员；按每次实例启动的既有账户快照处理。
- 新成员默认获得空间 `read`、`write`；已有成员跳过，不重复插入，也不覆盖管理员手工设置的只读权限。
- 成员写入失败则启动失败，不创建可推进但无法共享文件的实例；启动重试沿用现有幂等键。
- 工作流结束、模板调整、角色成员变化，不自动清除历史空间成员。

空间授权只能由通过现有工作流发起校验的服务端流程创建；调用人不能自行指定其他空间或待授权账户。实现使用已有存储边界的事务内方法，不从 Web 绕过接口直接写库，也不以管理员文件接口代替参与账户的文件权限。

### 4.2 实际操作与撤权

所有文件列表、预览、下载和上传都检查当前空间权限，不额外要求 MCP Tool 授权。自动加成员不向账户授予全局网盘管理权限，也不向所有账户开放文件工具。

空间权限与节点处理权分开：空间成员能读写文件，不代表可以提交其他人的节点或审批；节点操作仍沿用待办归属、账户状态和任务状态校验。

**空间 `write` 包含现有网盘的修改能力；节点独立路径和默认不覆盖是交接约定，不是防篡改隔离。** 首版按参与者互信处理，不承诺结果不可修改。文件引用带版本与摘要，读取时可以识别后续修改，不把已变更内容当作原提交内容静默使用。

手工移除成员后，后续文件访问及节点结果提交按当前权限拒绝，不能由下载描述或工作流读取接口绕过。已下载到本地的副本无法收回。

自动加入是“每次发起新实例”的动作，不做运行中持续补权。被移除账户如果仍被下一次实例选为参与者，会重新加入；需要持续撤权时，管理员应同时移除模板中的账户或相关角色资格，或停用账户。已有只读成员不会因新实例被自动提升为可写，无法归档时保留待办并提示权限不足。本期不增加拒绝名单或第二套授权优先级。

## 5. 节点结果归档与交接

### 5.1 Agent 节点

```text
读取任务及共享上下文 → 执行 → 上传明确交付的附件
→ Gateway 归档正式文本与 JSON → 保存文件引用并完成节点 → 下游读取
```

1. 任务读取增加共享上下文：`shared_space_id`、`instance_path_prefix`、当前节点提交目录以及已完成上游节点的文件引用。不改变原有 `input`、`output` 业务对象结构。
2. 现有客户端通过 `routes.enterprise-workflow.ts` 的完成对账提交最终文本；在该链路接入归档，不只靠提示词要求 Agent 自行上传。
3. Gateway 在完成节点时将 `output.text` 保存为 `result.md`，并将完整原有 JSON 输出保存为 `result.json`。其他 MCP Client 提交非文本 JSON 时至少归档 `result.json`，不猜测正文内容。
4. 附件由 daemon 使用当前项目和登录身份读取，经 Gateway 上传；只接收明确交付的文件，不扫描整个工作区。上传完成后保存文件 ID，并随原有完成请求提交。
5. Gateway 从任务推导模板、空间、实例和节点路径，验证附件真实存在、属于本次节点提交且调用人有权访问；拒绝伪造引用、其他模板或实例的文件，以及外部 URL。
6. 文件上传、文本归档或引用校验失败，不完成节点、不生成下游待办。下游通过已落库的引用读取，不依赖模型转述或其他账户本地路径。

归档服务先检查当前任务、身份、空间写权限及已有幂等结果，完成文件写入后，在原有完成事务中再次校验任务状态与权限，并一起保存引用、完成节点、创建下游待办。不要在数据库行锁期间执行长时间文件上传，也不建设数据库与 OSS 的分布式事务。

归档成功但节点提交失败时，重试复用同一提交目录与匹配的文件。提交摘要包含输出及附件引用；相同幂等键但内容变化返回冲突。Agent 结果归档前，复用共享网盘的同路径幂等上传，在提交目录写入内部校验文件 `submission.sha256`，固定首次请求摘要；该文件不进入正式结果引用，不传递给下游。多候选账户并发提交仍只有一个账户能完成节点；未获胜或终止后遗留的上传文件本期保留，不影响下游正式引用，不新增清理任务。

### 5.2 审批与结果读取

审批继续沿用现有接口：把决定、审批意见、处理账户和时间归档为该节点的 `result.json`，归档成功后再提交审批与推进状态。保留审批通过时原有业务输入向下游传递的行为，不要求审批人手工上传结果。

文件引用统一包含 `file_id`、`logical_path`、`revision`、`sha256`，名称、类型和大小从共享网盘元数据获取。Gateway 返回引用但不返回存储密钥、对象存储凭据或永久公开链接；文件下载始终经过当前账户授权。

非当前实例参与者但已是模板空间成员，可以从网盘读取实例文件，不因此获得该实例的工作流详情或待办处理权限。被撤销空间权限的历史参与者仍可按原有规则看到实例列表和状态，但包含正式结果的任务、实例及审批详情读取必须同时检查空间 `read`，无权时拒绝返回正文，包括原有 `input`、`output.text` 和审批意见。检查放在服务端共享读取边界，覆盖 HTTP、MCP 与审批详情入口，避免仅限制下载；文件权限错误不能伪装成空结果。管理员文件读取沿用既有明确的管理权限，不因工作流可管理就自动绕过网盘授权。

## 6. 最小数据与接口调整

| 位置 | 首版调整 |
| --- | --- |
| `workflow_templates` | 增加可空 `shared_space_id` 外键及非空值唯一约束；旧模板可空，新模板必须绑定 |
| `workflow_node_tasks` | 增加 `artifacts_json`，默认 `[]`，保存本节点正式提交的引用；不新建文件关联表 |
| 实例与任务响应 | 增加共享上下文及文件引用；实例目录由实例 ID 推导，不重复落库 |
| 节点完成请求 | 保留 `output` 与 `idempotency_key`，新增可选附件引用；服务端补齐正式结果引用 |
| daemon 运行关联 | 在现有工作流 Run 关联中持久化附件引用，账户切换或重启不丢失；不新增任务队列 |

新增数据库字段必须通过迁移。引用列表和上传大小受既有请求及文件限制约束；保留原有业务 JSON 与文本输出以兼容现有交接，不将附件二进制或正文内联进工作流 JSON。界面主要展示简短摘要及文件引用，不把大文件加载进详情。

附件上传增加任务范围接口，例如 `POST /api/v1/app/workflow-tasks/:id/files`：沿用认证与现有流式文件上传约定，接收文件名、提交幂等键、大小、摘要和文件内容；服务器决定空间与路径。文件读取复用现有共享网盘接口，不新建下载协议。

daemon 在已有 Runtime 工具注册边界提供当前工作流文件上传、读取能力，复用共享网盘管理器的本地路径与下载校验；绑定当前账户、Gateway、任务、Run 和项目，不接收任意账户、空间、外部 URL 或项目外文件路径。其他 MCP Client 可通过相同受控 HTTP 上传接口提交附件，服务端完成接口同样自动归档结果。

工作流自身的任务身份、待办归属与审批授权规则不变。原有客户端和直接 MCP 调用都必须经过同一 Gateway 归档完成逻辑，不能仅修改客户端而留下绕过归档的完成入口。

## 7. 开发位置与顺序

| 阶段 | 主要代码位置 | 完成标准 |
| --- | --- | --- |
| 1. 数据授权合并 | `server/internal/mcpgateway/service.go`、`skillcontributionsmcp/client.go`、管理台 MCP 授权界面 | 数据权限单独存在即可发现、查询和导出；独立工具授权不能绕过数据权限 |
| 2. 模板空间与成员 | `server/db/migrations/`、`server/internal/workflow/service.go`、`sharedfiles/`、`dataaccess/` | 模板只绑定一个空间；实例目录隔离命名；启动按参与名单幂等加成员 |
| 3. 归档与文件交接 | `server/internal/mcpserver/workflow.go`、`server/internal/server/workflow_http.go`、共享文件服务 | Agent 与审批完成前强制归档，保存引用后才推进；受控附件上传可用 |
| 4. 客户端接入 | `client/apps/daemon/src/api/routes.enterprise-workflow.ts`、`enterprise/`、`client/packages/protocol/src/workflow.ts`、`client/apps/web/src/features/workflow/` | 完成对账、附件交付、下游读取和结果入口完整，桌面与浏览器共用 |
| 5. 管理台补充 | `server/web/src/pages/workflow.tsx`、`server/web/src/lib/workflow-api.ts` | 模板展示空间入口，实例展示目录及节点正式文件，不另建管理页面 |

共享文件逻辑仍由 Gateway 管理，本地路径读取和 Runtime 接入留在 daemon，Web 只做展示与交互。只在现有存储实现补充必要的事务内方法，不复制网盘业务实现。管理台界面遵循 `docs/design/design.md` 与 `docs/frontend/frontend-development-guidelines.md`。

历史兼容：不批量回填旧聊天或输出文件。旧实例详情可继续读取；升级后旧的运行中实例首次文件操作或提交时补齐模板空间和参与成员，随后执行相同归档规则。补建成员只执行一次，避免手工撤权后被每次读任务重新加入；以模板记录锁和明确的实例初始化标记保证幂等。可在 `workflow_instances` 增加默认 `false` 的 `shared_files_initialized` 字段，新实例在启动事务内置为 `true`。

## 8. 验收标准

| 场景 | 必须满足的结果 |
| --- | --- |
| 只有 Skill 数据查看权限，无 MCP Tool 授权 | 页面、Agent 查询与实际 CSV 下载均成功，聚合及单上游入口一致 |
| 只有旧 MCP Tool 授权，或撤销数据权限后使用旧会话 | 工具不获数据授权；直接调用和下载仍拒绝；其他 MCP 不受影响 |
| 数据权限服务故障、账户或 Agent 停用 | 拒绝访问，不以工具授权兜底 |
| 同一模板多次、并发执行或重试 | 只有一个模板空间；不同实例使用不同前缀；相同启动键不新增实例或授权 |
| 角色节点、多候选 Agent 节点与审批节点 | 启动时全部有效参与账户加入空间；已有成员权限不被覆盖 |
| 新成员查看历史实例与其他模板 | 可读本模板全部历史结果，无权读未授权模板；无额外待办处理权 |
| 手工撤权与只读降权 | 运行中不自动补权；后续文件操作及归档按当前权限拒绝；新实例重新加入规则符合第 4 节 |
| Agent 文本、JSON 和明确交付的附件 | 正式内容均可从网盘获取；下一账户无需上一账户电脑即可读取 |
| 上传失败、审批归档失败或伪造附件 | 不推进节点；不能引用其他实例文件、越界路径或公开 URL |
| 完成重试、多个候选并发提交 | 幂等结果稳定，仅一次节点推进；未获胜上传不进入正式引用 |
| 文件被修改、账户切换或无存储配置可用 | 版本不一致、身份变化、存储错误明确失败，不静默替换或返回零结果 |
| 旧模板、旧运行中实例与已结束实例 | 按历史兼容规则处理，补建只执行一次，不回填已结束实例文件 |

先在现有 Go 与客户端测试中补充上述关键回归，服务端集成测试使用隔离数据库。客户端代码落地后运行 `desktop:preflight:local`；管理台执行已有测试、类型检查与构建。记录实际结果，未通过不得宣称可发布。本次只保存设计文档，不代表已执行代码验证。
