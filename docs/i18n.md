# 双语文档维护规范

[English](./en/i18n.md) · **简体中文**

## 目录约定

为避免破坏现有链接，中文文档保留在当前路径，英文翻译放在对应的 `en/` 镜像目录：

```text
docs/
├── architecture.md              # 中文原文
├── en/
│   └── architecture.md          # English translation
└── zh-CN/
    └── README.md                # 中文首页

server/docs/
├── getting-started/
│   └── development.md           # 中文原文
└── en/
    └── getting-started/
        └── development.md       # English translation
```

图片和其他共享资源继续放在 `docs/assets`，不要按语言重复复制。历史文档可以只保留中文，但新增或更新的高频使用文档应提供英文翻译。

## 翻译优先级

1. README、快速开始、安装部署、配置、客户端接入、安全和贡献指南。
2. 架构、权限、HTTP API、MCP、开发规范和运维手册。
3. 历史设计、规划、讨论稿和客户专属材料，可按需要翻译或明确标记为仅中文。

## 文档要求

- 每份双语文档顶部提供语言切换链接。
- 命令、环境变量、API 路径、字段名、错误码、版本号和代码示例保持原意，不翻译技术标识。
- 权限、安全、迁移和部署内容必须人工复核，不能只依赖机器翻译。
- 英文翻译与中文原文应包含相同的当前能力、限制和警告；规划能力必须明确标记。
- 链接应根据文档所在目录调整，图片尽量引用共享资源。
- 修改中文原文时，应同步更新英文翻译；暂时无法同步时，在 PR 中明确列出待翻译内容。

## 验证

双语检查覆盖第一批要求翻译的文档、相对链接、图片和代码块：

```bash
python3 scripts/docs_i18n_check.py
```

脚本只验证文档结构和链接，不判断翻译是否准确；技术内容仍需人工审阅。
