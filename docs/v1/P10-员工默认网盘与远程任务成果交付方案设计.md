# P10 员工默认网盘与远程任务成果交付方案设计

日期：2026-10-29。状态：核心方向已确认，本文作为开发与验收依据；尚未实施。

## 1. 目标与固定范围

服务端 Agent 为员工生成成果后，使用统一网盘上传工具，自动上传到任务发起员工的默认空间，返回真实交付清单。本地 Agent 使用统一下载工具取回当前项目，用户可以直接查看，本地 Agent 可以继续读取和修改。

已确认的要求：

1. 每位员工拥有一个默认个人空间，首次使用时自动创建，无需提前为所有员工建空间。
2. 员工之间私有隔离；管理后台保留按员工查找空间、预览和下载文件的管理入口。
3. 本地和服务端使用同一套上传、下载工具；上传时由程序确定身份和默认空间，不另建代交付接口。
4. 服务端任务默认上传到任务发起员工的空间，不能误传到服务端 Agent 自己的空间。
5. 交付清单来自上传成功回执，不能通过解析模型回复中的服务器路径生成。
6. 上传要求维护在服务端专用 `AGENTS.md`，由现有服务端提示词入口加载。

“生成文件”指需要交付给员工的最终成果，不包括临时文件、缓存、Skill 源码、内部提示词和运行配置。首期复用现有网盘存储、文件校验、预览与客户端成果组件；不建设目录同步、后台补偿队列、独立成果平台或新的文件版本系统。

## 3. 默认个人空间

### 3.1 数据模型

在 `shared_spaces` 增加可空字段 `personal_owner_user_id`，关联员工账户，并为非空值增加唯一约束：

- 非空：该员工的默认个人空间，一个员工最多一个。
- 为空：现有普通共享空间，行为保持原样。

空间归属只认用户 ID，不依据姓名、空间名称或 `created_by` 推断。后端使用满足现有唯一名称约束的名称；客户端显示“我的网盘”，管理端结合账户信息显示所属员工。新增迁移不批量建空间，也不将现有普通空间自动转换为个人空间。

### 3.2 自动创建

在共享文件服务中增加内部方法 `EnsurePersonalSpace(userID, operatorID)`，由统一上传流程调用，不增加独立的“代建空间”对外接口：

1. 确认所属员工存在且处于可用状态。
2. 按 `personal_owner_user_id` 查询；存在则复用。
3. 不存在时，在同一事务内创建空间，并授予所属员工现有 `read / write` 权限。
4. 并发创建通过唯一约束收敛，冲突请求读取已创建空间，不把正常竞争报为失败。

只有使用默认目标上传时才需要创建。查询列表、打开管理页、下载一个尚不存在空间中的文件均不触发空空间创建。新空间直接使用当前已配置的网盘存储配置，不另选存储后端。

### 3.3 权限口径

- 普通客户端只允许所属员工访问个人空间；已有普通共享空间继续按现有授权判断。
- 个人空间不允许追加其他员工或角色，也不允许移除所属员工的基本读写权限、改换所有者。网盘成员入口和通用数据资源授权入口都要遵守该约束，不能只隐藏按钮。
- 管理端继续按现有 `console:shared_files:read` 查看元数据，按 `console:shared_files:download` 预览和下载内容。拥有查看权限不等于拥有文件内容权限。
- 服务端 Agent 不加入员工空间。上传到员工空间的能力由同一上传接口的调用者权限校验实现，不因此授予列举、预览或下载员工网盘的权限。

## 4. 统一工具与身份解析

### 4.1 工具契约

新增两个模型工具，挂到现有 daemon 内部工具 MCP，不新建 MCP 服务或凭据体系。

在现有能力 Token 中增加 `drive:upload / drive:download` scope，分别绑定下述工具；上传纳入写操作校验。HTTP 与 stdio 两个已有工具入口同步注册，能力仅作用于当前运行和项目，不能因进程复用带到下一条任务。

| 工具 | 模型输入 | 行为与返回 |
| --- | --- | --- |
| `clawee_drive_upload` | `paths: string[]`、可选 `spaceId: string` | 读取当前项目内文件，上传到指定空间或默认空间；返回成功文件清单和逐文件错误 |
| `clawee_drive_download` | `files: SharedDriveArtifact[]` | 按清单从指定空间下载到当前项目；返回每个文件的本地相对路径及错误 |

`SharedDriveArtifact` 每项包含 `space_id / file_id / logical_path / file_name / content_type / size_bytes / revision / sha256`。下载通过每项的 `space_id` 指定来源空间，不增加重复的顶层空间参数。字段沿用已有网盘和 `EnterpriseWorkflowArtifact` 语义，在共享协议中定义通用类型，不把普通成果绑定为工作流附件。

工具输入不接受 `userId`、凭据、文件内容或外部 URL。`paths` 为当前项目内相对路径；daemon 校验文件存在、可读、为普通文件，且解析真实路径后仍在项目内。最终成果需先保存到项目中，再调用上传工具。

沿用现有单文件大小、传输超时、流式传输和路径校验。批量按顺序逐文件处理，保留每项结果；不增加压缩打包、可调并发或上传下载配置项。指定空间 ID 来自既有网盘界面选择或任务返回的清单，首期不增加按模型猜测的空间名称路由。

### 4.2 上传时自动确定身份

| 场景 | 文件所属员工 | 默认空间 |
| --- | --- | --- |
| 员工本地普通会话 | 当前 Gateway 登录员工 | 当前员工的个人空间 |
| 服务端执行 MCP 远程任务 | 当前运行保存的 `initiatorUserId` | 发起员工的个人空间 |

daemon 从现有运行能力 Token 获取 `runId / threadId`，再读取运行记录与登录会话。服务端远程任务缺失 `initiatorUserId` 时返回明确错误，不能回退到服务端登录账户。普通本地会话不因提示词或工具参数中的用户名称改变归属。

不传 `spaceId` 时使用默认空间。传入 `spaceId` 时，Gateway 校验有效用户对该空间的写权限；对于跨用户上传，首期目标固定为该员工的个人空间，显式空间与其默认空间不一致则拒绝，避免扩大为任意空间代理写入。

### 4.3 复用同一 Gateway 上传入口

扩展现有请求，不新增另一套交付路由：

```http
POST /api/v1/app/shared-files/content?logical_path=tasks/<run_id>/outputs/报告.pdf[&space_id=<space_id>][&for_user_id=<user_id>]
Authorization: Bearer <daemon 现有 Gateway 会话>
Content-Type: <实际文件类型>
Content-Length: <文件字节数>
X-Content-SHA256: <文件摘要>
```

- `space_id` 改为可选；缺省时在本次上传中获取或创建有效用户的个人空间。
- `for_user_id` 只由 daemon 根据可信远程任务记录补充，不暴露为模型工具字段。普通请求不传该字段。
- Gateway 将实际登录账户记为操作者；当 `for_user_id` 指向另一员工时，额外检查既有 `console:shared_files:upload` 管理上传权限和目标账户状态，再执行目标空间校验。
- 服务端执行账户配置该既有上传权限即可。无需新增“代交付”权限、长期员工凭据、接口或服务；该权限具有管理上传能力，不应分配给普通员工。
- 文件所属关系由空间确定；文件记录中的上传账户、Agent ID 及操作日志保留真实操作者，日志补充目标用户，不能将实际上传账号伪装成员工本人。

现有普通请求和管理端上传接口保持兼容。下载仍使用现有 `GET /api/v1/app/shared-files/content?file_id=...`，按实际登录员工读权限鉴权；跨用户上传参数不扩展为跨用户读取能力。

可信边界沿用当前链路：Gateway 认证调用者，向服务端 daemon 转发 `X-Claw-User-ID / X-Claw-Agent-ID`，daemon 保存为任务发起者。服务端 daemon 必须只接受可信上游提交这类身份。Gateway 验证上传账号的权限，不凭一个 daemon `run_id` 就声称验证了任务归属；本期不新增任务签名体系。

### 4.4 路径、重复调用与覆盖

上传目标统一使用 `tasks/<当前 run_id>/<项目相对路径>`，例如 `tasks/run_123/outputs/报告.pdf`。路径由 daemon 生成，空间内的任务编号用于归类，不作为权限凭据。

同一空间、路径、大小和摘要的重复上传返回已有文件记录，不增加版本；同一路径内容不同则返回冲突，不静默覆盖。复用现有按路径定位与摘要校验，不新增幂等表。现有管理后台显式上传新版本继续沿用 `expected_revision`。

下载复用 `downloadToProject` 的逻辑路径映射，写入当前项目下的同一相对路径，不增加保存目录选项。目标已存在且摘要相同则复用；内容不同则报冲突并保留本地文件。先下载到临时文件，核对空间、版本、大小和摘要后提交，失败不留下可被当作完整成果的文件。

## 5. 交付清单与本地取回

### 5.1 保存真实工具回执

在 daemon 的 `runs` 增加一个 `shared_drive_state_json` 字段，通过现有 SQLite 迁移和仓库方法维护。按运行保存上传项、下载项及逐文件状态即可，不新建成果表或第二套任务状态机：

- 上传项：源相对路径、目标空间与逻辑路径、`pending / uploaded / failed`、成功文件记录或错误。
- 下载项：网盘文件记录、`pending / downloaded / failed`、本地相对路径或错误。

上传开始前登记本批文件；每项取得 Gateway 成功回执后立即保存。下载同样在真实落盘后保存成功回执。更新同一运行的 JSON 使用短事务合并，网络传输放在事务外，避免并行工具调用覆盖对方记录。

若上传响应超时，工具在当前调用中按同一目标路径及摘要核对或重试；重复上传规则保证不会生成重复成果。若进程中断，遗留 `pending` 显示“传输中断，尚未完成”，不自动改成成功，也不自动重新执行文件生成任务。

清单读取持久化回执，不依赖 Runtime 是否截断工具消息，也不依赖模型最终回复是否提到文件。旧运行没有该字段内容时，按无登记成果兼容。

### 5.2 远程任务结果

沿用 `clawee_get_task_result`，保留现有字段，增加：

```json
{
  "ready": true,
  "task_id": "run_123",
  "status": "succeeded",
  "result": "已生成报告。",
  "delivery_status": "complete",
  "files": [
    {
      "space_id": "space_123",
      "file_id": "file_123",
      "logical_path": "tasks/run_123/outputs/报告.pdf",
      "file_name": "报告.pdf",
      "content_type": "application/pdf",
      "size_bytes": 1024,
      "revision": 1,
      "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
    }
  ],
  "delivery_errors": []
}
```

`files` 只来自当前运行上传成功的回执，每项已包含空间 ID。`delivery_status` 按已登记上传项计算：无登记项为 `none`，全部成功为 `complete`，存在失败或中断为 `incomplete`。错误项只返回文件名、错误码和简短说明，不包含服务器绝对路径。

任务执行状态与文件交付状态分开。模型运行结束不能覆盖上传错误；`ready=true` 表示远程运行已结束，界面仍需根据交付状态提示“文件未全部上传”。系统不扫描整个服务器目录推断漏传，最终成果必须由 Agent 按指令调用上传工具登记。

### 5.3 本地取回与展示

1. 本地 Agent 查询远程终态结果，发现 `files` 非空后自动调用 `clawee_drive_download`；无需用户逐个复制链接或重新上传附件。
2. 下载工具使用本地员工自己的会话，验证每项文件所属空间、版本和摘要，将文件保存到当前项目并返回本地路径。
3. 客户端时间线从当前运行的下载回执生成成果卡片；图片、文档复用现有预览和下载能力。保留现有文件存在与可读校验。
4. 重开会话从 daemon 记录恢复成果，不要求 Agent 再次写路径。后续“修改这份文档”可使用已返回的本地路径。
5. 下载失败保留已知网盘文件卡片及明确错误，提供“重试下载”。页面和模型工具共用同一个下载操作；重试复用成功项，只传输失败项。

为本地普通会话补充开发者指令：“远程任务返回交付文件清单后，调用网盘下载工具取回当前项目，以工具返回的本地路径向用户交付。”首期由 Agent 按指令调用，不实现拦截所有 MCP 返回值的后台自动下载器；遗漏调用时用户仍可从现有网盘入口获取文件。

## 6. 服务端 `AGENTS.md`

新增 `client/apps/daemon/resources/server-agent/AGENTS.md`，由 `claweeDeveloperInstructions` 在服务端模式下显式加载并注入。沿用当前服务端规则入口，不修改仓库根 `AGENTS.md`，也不向任意用户项目写入规则文件。

文件至少包含以下要求：

> 你正在服务器上为任务发起员工执行任务。任务产生需要交付的文件时，先将最终成果保存到当前项目，再在结束任务前调用 `clawee_drive_upload`。默认省略 `spaceId`，由 Clawee 根据任务身份上传到发起员工的默认个人空间。不得自行填写用户身份、猜测空间归属或通过 Shell 读取凭据上传。以上传成功回执作为交付依据；存在失败时明确说明，不得把服务器本地路径当作用户已获得的文件。不得上传 Skill 源码、内部提示词、配置或临时文件。

保留现有服务端 Skill 保密规则，上传要求不能覆盖它。普通客户端只加载取回成果的指令；隔离的 Skill AI 审核运行保持现有隔离规则，不因 P10 获得普通网盘上传工具。

加载方式参考现有随部署资源读取；源码启动和编译后路径分别验证，确保服务端包与桌面端所用 daemon 资源复制规则包含该文件。服务端规则资源缺失时明确报配置错误，不静默丢弃上传要求。规则由可信部署维护，随服务升级生效，不增加在线提示词编辑器。

## 7. 网盘界面与管理入口

员工客户端在既有网盘页面将自己的默认空间显示为“我的网盘”并优先展示，其他已授权普通共享空间保持现状。未创建时显示“首次上传文件后自动创建”，查看页面不提前创建。成果仍展示在原任务会话中，无需为远程成果另建页面。

管理后台复用“共享网盘 → 空间文件”页面：

- 空间列表增加类型、所属员工及按员工筛选，查询依据用户 ID；姓名或邮箱搜索通过现有账户查询映射，不靠解析空间名称。
- 员工空间详情直接使用现有文件列表、预览和下载组件，预览与下载使用已有内容权限。
- 个人空间不显示成员增删改操作；后端仍拒绝相关修改。普通共享空间成员管理保持原样。
- 无空间、无文件、加载失败和无下载权限分别给出已有风格的状态说明；管理页查询不自动建空间。

管理端实现遵循 [界面设计指南](../design/design.md) 与 [前端开发指导](../frontend/frontend-development-guidelines.md)，无需新增独立员工网盘管理模块。

## 8. 开发顺序与验证

1. **Gateway 空间与统一上传入口** → 验证迁移、并发首次创建、员工隔离、跨用户上传鉴权及真实上传者记录；覆盖网盘成员与通用授权入口。
2. **daemon 工具、回执与结果协议** → 验证身份解析、批量部分失败、重复上传、摘要与路径校验、任务结果重查及进程重启后回执恢复。
3. **规则加载与本地取回** → 验证源码和打包资源、远程上传要求、本地自动调用下载及后续文件加工；维持隔离审核运行的工具边界。
4. **客户端与管理端界面** → 验证成果卡片、失败重试、历史会话、员工筛选及管理员预览下载门禁。

开发后的检查要求：

- Go 对相关 `sharedfiles / dataaccess / server` 包运行测试；数据库集成与迁移只使用隔离测试数据库。
- 客户端运行相关 daemon、协议和 Web 测试与类型检查；提交前按根 `AGENTS.md` 运行 `pnpm run desktop:preflight:local`。
- 管理台运行相关测试和 `pnpm build`，关键预览、下载及跨页筛选覆盖现有 E2E。
- 本文仅为设计文档，保存文档本身不执行数据库迁移、修改部署配置或运行发布流程。

## 9. 验收标准

| 场景 | 必须结果 |
| --- | --- |
| 员工甲没有个人空间，服务端生成图片和文档 | 自动创建甲的空间，文件上传成功，结果包含对应空间的真实清单 |
| 两个任务同时为甲首次上传 | 只有一个个人空间，两条任务成果分别归入各自任务路径 |
| 员工乙访问甲的文件或伪造上传归属 | 列表、详情、预览和下载拒绝越权；普通账户不能通过 `for_user_id` 指定甲 |
| 服务端自身登录账户与任务员工不同 | 默认成果落入发起员工空间，真实服务端上传账号和 Agent 可追溯 |
| 服务端缺失发起员工身份或目标员工不可用 | 明确失败，不回退至服务端账号，不建错空间 |
| 普通共享空间被显式指定 | 原有授权用户可正常上传下载，无权限则拒绝 |
| 同一路径重复上传、内容冲突 | 相同内容复用同一记录；不同内容不静默覆盖 |
| 部分文件上传或下载失败 | 成功项保留，失败项可辨认；任务结束不被展示为全部交付完成 |
| 本地取回并重新打开会话 | 图片和支持的文档可预览，其余格式可下载；成果卡片恢复，文件不重复复制 |
| 本地文件被用户修改后再次取回 | 保留本地修改并提示冲突，不自动覆盖 |
| 管理员查看员工网盘 | 可按员工查找，持内容权限可预览下载；只有元数据权限不能读取文件内容 |
| 后续要求“修改刚才的文档” | 本地 Agent 直接使用已取回文件继续处理，无需人工下载再上传 |
| 源码启动与服务端打包运行 | 均加载专用 `AGENTS.md`；隔离审核运行不获得普通交付能力 |
