# 技能空间接入外部审批方案（首期钉钉 OA）

> 状态：方案已确认，供开发与验收使用；钉钉应用权限和模板字段须在目标企业联调确认。
>
> 日期：2026-09-22。范围：Gateway Skill Hub 及 `server/web` 技能管理界面；不改变本地个人 Skill 的发布方式。

## 1. 目标与边界

技能空间可选择使用钉钉 OA 审批。人工上传的版本由上传者发起 OA；整个审批实例通过后，具有发布权限的人再在 Clawee 手动发布该版本。审批通过不自动发布，钉钉回调不直接修改 `current_version_id`。Git 同步版本不接入 OA，仅允许具有现有发布权限的人手动发布。

- 首期复用当前钉钉登录的企业内部应用及已绑定的员工钉钉身份。上线前核实该应用可获得 OA 实例创建、查询和事件订阅权限，且审批模板允许该应用发起。
- 只有配置为钉钉审批的空间改变行为；其他空间沿用现有本地审批或上传者自行发布规则。首期只实现 Skill 人工上传版本的钉钉审批，不预留其他审批业务或平台的通用框架。
- 不做人工上传版本的管理员线下放行、自动发布、审批超时策略、Git 同步审批，也不建设通用审批引擎；不为 Git 同步的 `auto_publish` 补充新行为。

## 2. 现状与必须守住的门禁

当前版本使用 `skill_versions.approval_status` 的 `pending/approved/rejected`，空间使用 `skill_spaces.approver_user_id` 指定本地审批人。`server/internal/skillhub/approval.go` 与 `approval_postgres.go` 处理本地审核；`server/internal/skillhub/postgres_store.go` 的 `setCurrentVersion` 决定是否允许发布。无本地审批人时，上传者还可经 `/skills/current-version/own` 自行发布。`server/web/src/pages/skill-detail.tsx` 也按是否有本地审批人显示相应操作。

因此不能只在前端增加“提交钉钉审批”按钮：钉钉空间的本地审核和上传者自行发布接口必须拒绝，管理员设为当前版本时由服务端按版本来源检查门禁。人工上传版本必须取得当前空间有效的 OA 通过记录；Git 同步版本不检查 OA，只能由管理员手动设为当前版本，且发布事务内将其版本结论设为 `approved` 并写入 `approved_space_id`，以符合现有已发布查询条件。审批配置变化时，仅将非当前版本的审批结论重置为待审；当前已发布版本的结论和 `current_version_id` 保持不变，继续可用。

## 3. 配置与数据

通过新的 `server/db` 顺序迁移增加以下数据，不修改既有迁移。已有 `workflow_instances` 是 Clawee 内部的模板、节点和任务流程；外部平台的审批实例不复用该表。

| 位置 | 最小字段 | 用途 |
| --- | --- | --- |
| `skill_spaces` | `approval_provider`，默认 `local`；`external_approval_template_id`，外部审批时必填 | 空间选择审批方式和模板；钉钉时模板 ID 即 `processCode`。保留既有 `approver_user_id`，仅在本地模式生效 |
| 新表 `skill_version_approval_instances` | `id`、`version_id`、`space_id`、`package_sha256`、`template_id`、`provider_instance_id`、`initiator_user_id`、`status`、`decision`、创建及更新时间 | 一行对应一次钉钉审批申请，保留结束及作废的历史申请 |

`status` 区分 `submitting/running/finished/terminated/failed/invalidated/uncertain`，`decision` 仅在正常完成后取 `approved/rejected`；版本的发布结论仍写既有 `skill_versions.approval_status`。对非空的 `provider_instance_id` 建唯一约束，并以部分唯一索引保证同一版本同一时刻最多一条 `submitting/running/uncertain` 申请。`finished + approved` 的申请不可重提；`finished + rejected`、`terminated`、`failed` 可由上传者重提；`submitting/running/uncertain` 不可重提。申请表不对 `version_id` 建全局唯一约束，以保留历史。

调用钉钉前先持久化 `submitting` 申请；确定未创建实例时标记 `failed`，结果或本地保存不确定时标记 `uncertain`，禁止自动重试。管理员经钉钉核实后，可对 `submitting/uncertain` 申请执行两种有审计的恢复操作：确认实例未创建并标记 `failed`，或填入查实的实例 ID 并查询同步；不能仅凭超时推断未创建。恢复前该版本不可重提。空间、包摘要和模板快照限定申请所批准的内容。空间迁移沿用现有撤销发布和重置版本审批的行为，并在同一事务内使原申请失效；旧实例的迟到事件不能批准迁移后的版本。迁移后如目标空间为钉钉模式，上传者可按新空间模板重新提交。

钉钉模块负责发起、查询、验证并解析事件；Skill Hub 存储层负责申请记录、幂等、版本结论及发布门禁。申请状态与版本结论使用同一个数据库事务更新，不单设跨业务审批包。

审批方式或模板变更时，若该空间存在 `submitting/running/uncertain` 申请，则拒绝变更；否则在同一事务内作废该空间全部旧申请，并仅重置非当前版本的审批结论。迁移有进行中申请的 Skill 同样拒绝。再次切回原模板也不能复用旧批准记录；当前已发布版本保持可用。仅 `status=finished` 且 `decision=approved`、未作废并与当前空间、模板、包摘要匹配的申请有效。

Gateway 在现有 `dingtalk` 登录配置之外增加独立的 OA 启用开关和事件回调 Token、EncodingAESKey；沿用应用 Client ID/Secret，不更改 OAuth 登录回跳地址。OA 未配置完整时不允许将空间切为钉钉模式。HTTP 事件回调与登录回跳分开；若钉钉应用已有事件回调地址，须在同一事件入口分发，不能覆盖原回调。

## 4. 业务流程与接口

1. 管理员在技能空间设置 `approval_provider=dingtalk` 和 `external_approval_template_id`。界面隐藏该空间原有本地审批人设置，并显示钉钉审批方式；切换配置走现有空间管理权限并记录审计。
2. 上传仍只创建 `pending` 版本，不自动发起 OA。人工上传者在 app 技能中心的本人未发布版本列表或管理端 Skill 详情点击“提交钉钉审批”；仅允许本人上传、Skill 当前属于钉钉空间、版本尚未发布且符合上述重提条件时提交。未绑定钉钉身份时提示先绑定；Git 同步版本不提供提交入口。
3. Gateway 以现有账号身份记录中的钉钉 `ExternalUserID` 作为 `originatorUserId`，使用空间模板 ID 作为 `processCode` 调用钉钉 `POST /v1.0/workflow/processInstances`。表单只发送 Skill 名称、版本、变更说明、包 SHA-256 和指向 Clawee 受权限保护详情页的链接，不上传 ZIP、正文或密钥。成功后将 `processInstanceId` 保存为 `provider_instance_id`；创建中的提交需防并发，确定失败可重试，不确定结果需人工核对。
4. 新增独立的 OA 事件入口，按钉钉 HTTP 推送要求验证签名、解密和应答。只接受 `bpms_instance_change` 的实例事件：`type=finish` 且 `result=agree` 映射为申请 `decision=approved` 和版本 `approved`，`refuse` 映射为 `rejected`；`terminate` 记录终止并保持版本不可发布。事件中的实例 ID、模板编码须匹配申请记录；空间与包摘要不在事件中，由 Gateway 对照申请快照和当前版本核验。申请状态与 Skill 版本结论在同一数据库事务内更新；重复或迟到事件不再次改变结论，非最终任务事件不能批准版本。
5. 具有现有发布权限的人沿用 `/skills/current-version` 手动发布。钉钉模式下，人工上传版本在存储层同一事务中核验版本 `approved` 和当前空间的有效 OA 通过申请；Git 来源版本在该事务内直接完成上述手动发布及版本结论更新，不发起或校验 OA。本地审核 `/skills/versions/review`、自行发布 `/skills/current-version/own` 在钉钉空间均由服务端拒绝。Git 同步的 `auto_publish` 不新增发布能力，不能绕过手动发布权限。

接口沿用现有路由风格，具体契约如下；请求和响应仍遵循 Gateway 现有统一格式：

| 接口 | 请求与权限 | 结果 |
| --- | --- | --- |
| `PUT /api/v1/admin/skill-spaces/approval` | `space_id`、`approval_provider`、`external_approval_template_id`；现有空间更新权限 | 更新空间审批配置并审计 |
| `POST /api/v1/app/skills/versions/submit-approval` 及 admin 同名入口 | `skill_id`、`version_id`；认证的上传者，app 需空间写权限，admin 需现有版本上传权限 | 返回本地 OA 状态和钉钉实例 ID |
| `POST /api/v1/integrations/dingtalk/skill-approval/callback` | 钉钉签名与加密事件；不使用用户登录态 | 幂等更新申请和版本审批状态 |
| `POST /api/v1/admin/skills/versions/sync-approval` | `skill_id`、`version_id`；现有技能发布权限，仅允许已知实例 | 查询钉钉实例详情并复用回调的结果处理逻辑 |
| `POST /api/v1/admin/skills/versions/resolve-approval` | `application_id`、`resolution`（`not_created` 或 `bind_instance`）；后者还需 `provider_instance_id`；现有技能发布权限 | 仅处理 `submitting/uncertain` 申请，核实后标记失败或绑定实例并同步，记录审计 |

回调是独立的非用户登录接口，不能复用 OAuth 回跳。管理员同步仅用于漏回调，不增加周期性轮询或后台任务；没有实例 ID 的申请须先由管理员核实并通过恢复接口处理，不能猜测审批结果。

现有 admin 技能详情返回所有版本，可直接为每个版本增加最新申请信息，并在钉钉模式返回 `can_review=false`。现有 app 技能详情仅返回已发布版本，因此扩展 `/skills/own-pending-versions`：钉钉空间返回本人上传的全部未发布版本（包括审批中、驳回和通过），其他空间保持原有列表规则。两处均返回可为空的 `approval_instance` 对象，包含最新申请的 `id`、`status`、`decision`、`provider_instance_id`；页面据此展示“待提交、提交中、审批中、通过、驳回、已终止、提交失败、异常待核对”及钉钉审批单入口，作废的旧申请按待提交显示。Git 版本只显示管理员手动发布操作，不显示 OA 状态或提交入口。提交、同步和恢复后重新获取对应列表或详情。钉钉审批人若需查看 Clawee 中的 Skill 内容，仍须获得对应空间的读取权限；审批单链接不绕过 Clawee 认证。

## 5. 实施落点与验收

- `server/internal/config`、`server/internal/dingtalk`：OA 配置校验、发起实例、查询实例和事件验证；登录逻辑保持不变。
- `server/internal/skillhub`、`server/internal/server/skillhub_http.go`、`skill_spaces_http.go`：空间模式、申请记录与恢复、结果入库及发布路径门禁；内存和 PostgreSQL 存储行为一致，不复用内部 `workflow` 实例。
- `server/web/src/lib/skillhub-api.ts`、`pages/app-skills.tsx`、`pages/skill-detail.tsx`、`components/skill-spaces-panel.tsx`：空间配置、提交及状态展示；遵循 `docs/design/design.md` 与 `docs/frontend/frontend-development-guidelines.md`，不以按钮禁用代替服务端校验。

验收至少覆盖：未启用空间行为不变；人工上传版本未绑定钉钉账号、OA 未配置或发起失败均不能发布；钉钉空间的本地审核、自行发布和管理员直发人工上传版本均不能绕过 OA；整个实例通过后可手动发布，驳回/终止可重提但不能直接发布；Git 同步版本不提交 OA，只有具备发布权限的管理员可以手动发布，`auto_publish` 不自动发布；多次申请保留历史但同一版本不能同时有两张进行中的单，`submitting/uncertain` 核实后可恢复；重复、伪造、迟到、跨空间或包摘要不匹配的事件不改变结果；漏回调可按实例 ID 手动同步；切换模式或模板不会复用旧批准记录，新版本待审时旧发布版本保持可用。测试使用隔离数据库和钉钉模拟客户端，联调再用目标企业的测试模板验证真实权限、表单及事件。
