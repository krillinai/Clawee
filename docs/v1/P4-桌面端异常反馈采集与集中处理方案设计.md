# P4 桌面端异常反馈采集与集中处理方案设计

> 轻量反馈更新：当前实现已调整为默认只发送用户填写的问题说明、主动添加的截图、版本信息和白名单运行摘要，不采集会话正文、工具输入输出、附件索引或原始日志。本文后续的完整采集描述保留为原方案背景，不再代表常规反馈行为。
>
> “附加诊断信息”默认关闭；开启后仅提取最近一次运行关联的、最近 10 分钟内最多 200 条白名单诊断摘要，不发送请求路径、消息正文或请求标识。发送前展示实际脱敏内容，并要求用户确认。
>
> 新 manifest 使用可选 `collection_scope`：`basic` 或 `diagnostics`。范围内采集成功即为 `complete`，主动排除的数据不属于缺失项。维护方 Gateway 必须先升级以支持此字段，再分发新客户端；历史反馈读取保留兼容，客户端停止旧版完整草稿的发送和自动续传。
>
> 成功上传后，本地诊断副本和截图保留 24 小时，回执保留 7 天；不删除用户原始会话或运行日志。桌面应急导出继续仅写入用户选择的本地文件。

## 1. 目标与范围

### 1.1 首版必须交付

1. 桌面端接收问题描述和问题截图。
2. 汇总当前 Clawee 会话的全部已留存会话记录和相关日志，上传时不静默截断。
3. 私有化部署的客户无需在维护方实例注册账号，也能向维护方实例反馈。
4. 上传支持断网、进程重启、响应丢失后的安全重试和附件级续传。
5. 维护方管理台提供简单、高效的反馈列表、详情和处理状态操作。
6. 独立 `/mcp/feedback` 提供会话、日志、截图读取，以及反馈处理成功工具。
7. 反馈材料、上传凭证、中心管理权限和客户业务凭据严格隔离。

### 1.2 本期不包含

- 自动监听并上传所有会话、崩溃后未经授权自动外传。
- 上传整个 SQLite 数据库、整个 Codex Home、整个工作区或整机日志。
- 自动上传会话原附件正文；本期只收集附件元数据，用户主动添加的问题截图除外。
- 新建独立反馈服务、独立管理台、复杂工单流转、通知系统或自动修复系统。
- 客户端直传对象存储、公开附件 URL、任意第三方反馈接收地址。
- 浏览器无 daemon 时采集桌面原生日志，或为了反馈增加全屏系统截图权限。
- 首版 MCP 重新打开、删除反馈或批量修改状态；重新打开由管理台完成。

## 3. 部署与信任边界

### 3.1 接收地址

| 用途 | 地址 |
| --- | --- |
| 客户业务连接 | 客户配置的 Gateway，保持现状 |
| 反馈上报 origin | `https://gateway.clawee.work` |
| 上报 API 前缀 | `https://gateway.clawee.work/api/v1/feedback` |
| 管理台 | `https://gateway.clawee.work/admin/feedback` |
| 独立 MCP | `https://gateway.clawee.work/mcp/feedback` |

客户端代码中将反馈 origin 作为独立的受控常量，与业务 `gatewayEndpoint` 分离。首版不提供任意反馈地址输入框。开发测试可通过明确的开发配置指向回环测试服务，生产构建禁止该覆盖。

daemon 使用独立网络客户端，仅设置反馈协议所需的请求头，禁止复用客户 Gateway 客户端的默认 Authorization、Cookie、Agent 标识或模型凭据。HTTPS 验证不可关闭，禁止自动跟随重定向，防止材料和凭证发送到不同 origin。失败不得回退到客户服务器或其他域名。

维护方实例显式启用反馈接收模块；客户实例默认关闭接收模块，其公开上报路由与反馈 MCP 返回 404。接收模块开启但中心账号、RBAC、MCP 验证或私有存储缺失时，管理与 MCP 必须失败关闭，不能进入匿名或演示模式。

### 3.2 客户侧外传开关与用户授权

客户管理员可通过部署策略关闭外部反馈，客户端消费既有配置通道中的 `external_feedback_allowed` 布尔值；新增字段不携带上报密钥。策略缺失时默认允许用户主动反馈，不代表自动上传。已获策略为禁止时，本地立即禁止创建与发送，暂停尚未完成的队列。

策略执行至少在打开入口、采集前和每轮上传前检查。已知策略已过期且无法更新时暂停待发送队列，不绕过管理员禁用。客户未配置 Gateway 的纯本地模式不依赖客户账号，可按本地策略主动反馈。策略有效期和配置来源沿用已有企业配置机制，不另建策略系统。

用户提交前必须看到接收方、接收域名、当前会话范围、材料清单、大小和缺失项，明确确认外传。建议确认文案：

> 将问题描述、截图及当前会话的完整已留存记录和相关诊断日志发送给 Clawee 软件维护方 gateway.clawee.work。资料可能包含业务内容，请确认可以发送。

匿名指不要求中心账号，不保证内容不可识别；不能把“匿名”展示为“没有个人或企业数据”。自动脱敏是尽力而为，截图必须允许预览、移除和人工遮盖。客户出口网络不通时仅保留本地材料，可手动导出，不绕过网络政策。

## 4. 采集内容与完整性

### 4.1 “全部”的准确含义

采集对象是当前 Clawee `thread_id`，范围从该会话创建到固定快照边界，包含所有已留存记录，不是最后一轮 Run，也不是 UI 已加载的历史片段。

| 材料 | 内容与约束 |
| --- | --- |
| 用户反馈 | 描述、发生时间、可选复现步骤、用户主动提供的截图 |
| 会话历史 | 用户消息、助手消息、已记录工具调用及结果、错误、取消、状态变化；保留顺序和来源 |
| Thread 元数据 | 会话标识、创建时间、运行模式、脱敏后的工作区关联信息 |
| Run 元数据 | 当前 Thread 全部 Run，含排队、失败、取消，以及 Runtime Thread 关联 |
| Run 文件 | 已有白名单元数据文件、`events.ndjson`、`raw.redacted.ndjson`、`stderr.redacted.log`、`diagnostics.json`及定时任务关联诊断 |
| 客户端日志 | 当前会话相关 Desktop、daemon、Web 错误、网络请求失败和必要启动诊断 |
| 环境快照 | App、daemon、Runtime、Electron 版本，构建 SHA，OS/架构，模型标识与连接状态；不含密钥 |
| 会话附件索引 | 文件名、类型、大小、哈希、关联消息；本地路径脱敏，不上传文件正文 |

客户端新增日志关联字段 `thread_id`、`run_id`、`request_id`，不得为了排障新增秘密明文日志。全局日志无法关联会话时，默认不把整份文件外传；只收集预先定义的无正文进程生命周期/连接事件，manifest 标记关联能力不足。历史版本没有记录的 Web 错误、已轮转删除的日志不能补采。

“完整”不包括未暴露的模型内部推理，也不能恢复源系统本来就截断的工具输出。发现缺失、原始截断、读取失败或版本不支持时，记录原因；不得用空数组替代失败后标为 complete。

### 4.2 快照与会话轮换

1. 固定 `snapshot_at`，在短数据库读事务中记录 Thread、Run 集合和每个 Run 的事件最大序号。
2. 为每个相关日志记录已确认写入的读取字节上限；有界等待日志队列 flush，不停止当前任务。
3. 结合 Thread 和全部 Run 的关联，枚举历次 Codex Thread；历史恢复路径未保存完整关联时补充持久化映射，不能只读取当前 `codex_thread_id`。
4. 为 Runtime 历史源固定可用的文件长度或稳定记录边界。没有稳定游标/快照能力时说明该源的边界不确定并标记 partial，不能仅凭客户端时间戳假设一致。
5. 异步导出全部事件与历史；分页遍历到固定上限，不使用默认条数或简单设置一个巨大 LIMIT 来冒充全量。
6. 保留底层事件作为事实来源；展示用历史可以去重，但不能因为正文相同而删除两次真实调用。优先使用消息 ID、Run ID、事件序号及来源对账。

`snapshot_at` 是采集触发时间，不承诺跨数据库和多进程文件的原子一致性；真实范围由各来源的 watermark 描述。任务继续运行产生的新数据不进入本次反馈，补充反馈需要重新采集并重新授权。

### 4.3 manifest 协议

`schema_version` 首版固定为 1；新客户端生成未支持版本时，中心返回明确的不兼容错误，不悄悄忽略字段。manifest 作为创建请求的有界 JSON 保存，包含：

```json
{
  "schema_version": 1,
  "snapshot_at": "2026-09-18T08:00:00Z",
  "thread_id": "本地会话ID",
  "run_ids": ["本地运行ID"],
  "runtime_thread_ids": ["关联Runtime会话ID"],
  "watermarks": [{"run_id": "本地运行ID", "max_event_seq": 120}],
  "completeness": "complete",
  "redaction_policy_version": 1,
  "artifacts": [{
    "artifact_id": "客户端生成的随机ID",
    "kind": "conversation",
    "name": "conversation-0001.ndjson",
    "content_type": "application/x-ndjson",
    "size_bytes": 2048,
    "sha256": "脱敏后文件的64位十六进制摘要",
    "record_count": 20,
    "source": "thread_history",
    "part_index": 1
  }],
  "missing_items": [],
  "warnings": []
}
```

每个来源另记录预期数、实际导出数、读取边界、源截断标识和缺失原因；文件分片记录首尾记录位置。所有摘要基于最终脱敏后的上传字节。`completeness` 由客户端和中心分别判断，中心最终结果取更保守值；中心校验不能证明客户端确实上传了所有本地数据。

超大日志和会话按完整 NDJSON 记录拆成顺序分片，首版不上传压缩包。单条超大记录不能直接切断为无效 JSON，须报超限或在明确缺失项下提交 partial。截图仅允许 PNG/JPEG/WebP，实际解码验证，拒绝 SVG、HTML、可执行文件及伪造格式。

### 4.4 反馈专用脱敏

保留用户主动授权的消息正文、工具名、排障所需参数和输出，但遮盖密码、Token、Authorization、Cookie、私钥和已识别的敏感配置值。路径用稳定占位符替换用户目录及敏感路径前缀，保留文件扩展名和关联关系；不要上传整个环境变量表。

复用秘密识别基础能力，新增独立反馈脱敏入口及策略版本；原诊断导出继续保持其 prompt 字段遮盖行为，避免改变已有安全契约。客户端先脱敏，中心再校验，疑似漏脱敏的附件进入 quarantine，不允许后台正文/MCP/下载读取，也不能记录秘密样本。

## 5. 客户端职责与可靠上传

### 5.1 模块职责

- `client/apps/web`：会话反馈入口、描述与复现步骤、截图选择/粘贴/预览/遮盖、授权确认、采集和上传进度、本地反馈回执。
- `client/apps/daemon`：会话校验、快照、脱敏、文件生成、SQLite 队列、网络上传、重试、凭证安全保存、过期清理。
- `client/apps/desktop`：受限 Desktop Bridge，导出原生环境与指定范围日志；不接受任意文件路径，不由 renderer 读取日志目录。
- `client/packages/protocol`：本地请求/响应、反馈队列状态、manifest 类型和新增 Bridge 契约；HTTP JSON 与 Go 类型保持一致。

共用 Web 页面只实现一次；没有桌面 Bridge 时可提交会话反馈，但明确标记桌面日志 unavailable。不能展示无效原生按钮。首版使用用户选择或粘贴的截图，不增加系统屏幕捕获权限。

daemon 不可用时，Electron 提供受限本地应急导出：保存描述、截图和桌面启动日志，标记 partial；daemon 恢复后仍需用户确认才能上传。不要为了应急路径在 Electron 重写会话读取、队列和上传业务。

### 5.2 本地持久化

新增本地反馈队列表，通过 SQLite 迁移维护，至少保存：

- `local_feedback_id`、`client_feedback_id`、`thread_id`、固定中心 origin。
- manifest、用户授权时间、授权文案版本、快照目录。
- 队列状态、逐附件上传结果、重试次数、下次重试时间、脱敏错误码。
- 中心 `report_id`、恢复凭证/查询回执的安全存储引用、有效期。

状态为 `collecting / awaiting_consent / queued / uploading / submitted / failed / cancelled`。材料置于 daemon 私有目录下的随机反馈子目录，权限从严；凭证优先使用现有安全存储，无现成能力时使用仅当前用户可读的独立秘密文件，不明文放进普通 SQLite 字段、renderer 状态或导出包。

在第一次网络请求前生成并持久化 `client_feedback_id`、随机 `recovery_token` 和独立随机 `status_token`。这样即使创建响应丢失，也能使用相同请求恢复，而不是新建重复反馈。所有 Token 至少含 256 位安全随机熵，使用 Base64URL 编码。

### 5.3 上传与重试

先完成采集和预览，再确认发送；创建反馈后按附件流式上传，默认最多两个并发，查验已接收附件后跳过已完成项。首版支持附件级续传，不实现单文件字节级续传。

网络错误、408、429、5xx 采用带抖动的指数退避，起始约 2 秒、上限 5 分钟，并尊重 `Retry-After`。401 仅在恢复凭证仍有效时换发上传凭证；403、413、410 和确定的协议错误不盲目重试。持续失败转为可手动重试状态，不删除材料、不反复弹窗。

取消会停止后续请求；尚未提交的中心材料由限时清理任务回收。已上传资料不会因客户端取消自动消失，必须如实提示。客户禁用策略不会自动撤回已提交资料，撤回由维护方按数据治理流程处理。

### 5.4 本地 daemon 接口

以下路径相对 daemon 现有 API 根路径，继续使用现有本地认证与 Origin 防护；“中心匿名”不表示本地采集接口也可以由任意网页调用。

| 接口 | 行为 |
| --- | --- |
| `POST /feedback/drafts` | 接收 thread_id、描述、发生时间和复现步骤，创建本地草稿，不发送到中心 |
| `POST /feedback/drafts/:id/screenshots` | 有界上传本地截图，返回随机 screenshot_id；不接受任意磁盘路径 |
| `DELETE /feedback/drafts/:id/screenshots/:screenshotId` | 移除本地草稿截图；已生成快照须失效并重新采集 |
| `POST /feedback/drafts/:id/collect` | 开始异步采集，返回 202；固定草稿内容和快照边界 |
| `GET /feedback/drafts/:id` | 返回本地状态、进度、脱敏材料摘要、大小、缺失项与中心有限状态，不返回任何秘密凭证 |
| `POST /feedback/drafts/:id/send` | 接收授权确认、快照摘要和 accept_partial，校验未变更后进入持久化上传队列 |
| `POST /feedback/drafts/:id/retry` | 仅重试同一已授权且有效的快照，不自动重建过期反馈 |
| `POST /feedback/drafts/:id/cancel` | 取消本地采集/待发送任务，说明中心已接收资料不会立即删除 |

collect 完成后进入 awaiting_consent，send 成功排队返回 202；未 ready 的本地快照不能 send。用户变更描述、截图或采集范围时，应修改尚未冻结草稿或新建草稿，重新 collect 和确认；已有中心 report 的 manifest 不可更新。接口限制草稿数量与本地磁盘占用，关闭反馈策略时拒绝 collect/send/retry。

## 6. 权限与凭证设计

### 6.1 权限矩阵

| 主体/凭证 | 创建 | 上传自身附件/提交 | 读取公开状态 | 读取正文 | 处理状态 |
| --- | --- | --- | --- | --- | --- |
| 匿名请求 | 限流允许 | 否 | 否 | 否 | 否 |
| 部署上报凭证 | 限流允许 | 仍需单反馈凭证 | 否 | 否 | 否 |
| 单反馈上传凭证 | 否 | 有效期内允许 | 仅上传进度 | 否 | 否 |
| 单反馈恢复凭证 | 否 | 仅换发上传凭证和查进度 | 否 | 否 | 否 |
| 单反馈查询回执 | 否 | 否 | 允许 | 否 | 否 |
| 中心管理人员 | 非上报身份 | 非上报身份 | 按范围 | read/download 权限 | 按具体操作权限 |
| 中心 Codex Agent | 否 | 否 | 工具授权后 | read + 能力授权 + 数据范围 | resolve + 能力授权 + 数据范围 |

中心 Token、客户 Token、部署凭证、单反馈凭证使用不同验证入口，不能因字符串都是 Bearer Token 就互相接受。公开入口不使用浏览器 Cookie 认证，忽略客户会话 Cookie。

### 6.2 匿名创建与恢复

中心保存 recovery/status Token 的 SHA-256 哈希及有效期；上传 Token 由中心生成，仅保存哈希。校验使用安全比较，接口不回显恢复凭证或查询回执。部署凭证同样仅保存哈希，可轮换、撤销、绑定可信来源，不能读取任何反馈。

创建按 `client_feedback_id` 去重，恢复凭证是创建重试的证明：相同 ID 必须提供匹配的恢复凭证且不可变请求摘要一致，否则返回统一冲突错误；不能只凭 Idempotency-Key 查询他人创建响应。相同合法请求重试返回同一 `report_id`、进度和新上传凭证，不复制反馈。

恢复换发仅对未冻结且未过期反馈生效，轮换旧上传 Token。客户端换发前暂停并等待并发上传结束，避免主动轮换中断自己的请求。仅凭反馈 ID、客户端设备 ID 或客户名称不得恢复上传。

提交成功后禁止再改正文和附件，恢复凭证不得发放新的写入权限，但可以查询该次提交是否成功，解决提交响应丢失问题。查询回执只返回状态与单独保存的客户可见结论，不返回描述、会话、截图、客户归属、内部备注或存储地址。

### 6.3 管理与 MCP 授权

新增权限，加入权限目录、系统管理员默认权限及管理台权限映射：

- `console:feedback:read`：列表、描述、详情与在线诊断阅读。
- `console:feedback:download`：导出附件，要求同时具备 read。
- `console:feedback:investigate`：开始处理并记录处理人。
- `console:feedback:resolve`：标记处理完成。
- `console:feedback:reopen`：重新打开，必须写明原因。

首版中心反馈人员的数据范围为 `all_feedback`，显式授予，不能因持有普通中心账号、其他管理模块权限或能访问聚合 MCP 而获得反馈权限。Service 接收中心认证解析出的权限和范围，在读取列表、详情、附件及更新状态时统一校验，不能由请求参数覆盖。

MCP 继续检查现有账号活跃状态、中心 Agent 绑定和工具 Grant，反馈适配器再检查反馈权限与范围。首版不按匿名自报客户字段限制或提升权限；未来增加客户级访问范围时必须建立可信来源资源模型。

中心启用 MCP 时强制现有账号鉴权，Codex 使用中心签发账号 Token，并按现有协议提供中心注册的 `X-Claw-Agent-ID`。不拿客户身份映射成中心管理员，不接受上报凭证，不开放匿名反馈读取。

## 7. 上报 HTTP 契约

### 7.1 路由与公共约束

新增独立 `/api/v1/feedback` 路由组，复用统一响应封装、请求 ID 和错误处理，但不继承 appAPI 登录/客户 Agent 门禁。管理 API 挂现有 adminAPI，不能因接收模块匿名创建而放松管理鉴权。

成功响应使用现有统一响应风格的 `data`，列表增加 `meta.next_cursor/has_next`；错误沿用仓库既有格式，业务错误码在本模块定义。所有凭证响应、正文、状态、MCP 返回和下载使用 `Cache-Control: no-store`。错误不泄露存储路径、秘密、数据库异常或其他反馈是否存在。

| 方法与路径，均相对 `/api/v1/feedback` | 凭证 | 行为 |
| --- | --- | --- |
| `POST /reports` | 无或部署凭证 | 创建不可变反馈元信息及 manifest |
| `POST /reports/:id/upload-credentials` | recovery Token | 恢复进度并换发短期上传 Token |
| `GET /reports/:id/upload` | upload 或 recovery Token | 返回上传状态、附件 ID/接收情况、提交结果；不返回正文 |
| `PUT /reports/:id/artifacts/:artifactId` | upload Token | 上传 manifest 中已声明附件 |
| `POST /reports/:id/submit` | upload Token | 校验并冻结反馈 |
| `GET /reports/:id/status` | status Token | 返回有限的客户可见处理状态 |

upload/recovery/status Token 均置于对应接口的 `Authorization: Bearer <token>`，不出现在查询参数。部署 Token 仅在创建接口使用 `X-Feedback-Deployment-Token`，这个新头必须加入全链路日志脱敏配置。

### 7.2 创建请求

```json
{
  "client_feedback_id": "客户端生成的随机ID",
  "recovery_token": "客户端已安全持久化的随机恢复凭证",
  "status_token": "客户端已安全持久化的独立随机回执",
  "description": "问题描述",
  "occurred_at": "2026-09-18T07:58:00Z",
  "reproduction_steps": "可选复现步骤",
  "source_claim": {"customer_label": "用户主动填写的可选来源"},
  "environment": {"app_version": "实际版本", "platform": "darwin", "arch": "arm64"},
  "consent": {"policy_version": 1, "confirmed_at": "2026-09-18T08:01:00Z"},
  "manifest": {"schema_version": 1, "completeness": "complete", "artifacts": []}
}
```

以上 artifacts 为空仅为字段示例；正常完整反馈必须包含会话、环境及来源诊断清单，中心按 completeness 校验必需项。描述必填，1 至 10,000 字符；复现步骤最多 10,000 字符，全部创建 JSON 最多 2 MiB。来源和环境采用字段白名单，不接受任意配置转储。

首次创建返回 201 和 Location，合法创建重试返回 200。data 包含 `report_id`、中心显示编号、`upload_token`、Token 有效期、反馈到期时间、已接收附件清单与生效上传限制。不返回正文或其他反馈信息。恢复/回执有效期由中心确定并返回。

### 7.3 附件上传

使用二进制请求体，不用 Base64 或巨型 multipart。声明 Content-Length、Content-Type、`X-Content-SHA256`；中心与 manifest 比对大小、摘要、类型，并校验实际内容。manifest 中的 filename 仅作展示，不用于构造文件路径；ID 格式校验，存储键由中心生成。

首次成功返回 201；相同附件、相同摘要重试返回 200，不重复占用配额。已有附件内容不同返回 409，不允许覆盖。并发重复上传由数据库状态/唯一约束控制，临时文件不得覆盖已接收对象。

存储成功后再登记附件 received；数据库提交失败产生的临时/孤立对象进入持久化补偿清理任务。整个过程不把附件读入内存，不依赖客户端 Content-Length 作为唯一限额，按实际字节强制上限。

### 7.4 提交与部分资料

submit 请求包含 `manifest_sha256` 和 `accept_partial`。manifest 摘要为 RFC 8785（JCS）规范化后的 UTF-8 字节的 SHA-256，客户端和 Go 使用符合该标准的实现并共享测试向量，不手写简化版键排序。计数、字节数和序号限定为 JSON 安全整数，时间使用字符串，拒绝重复对象键；不可仅比较不同语言默认 JSON 编码的哈希。不可变请求摘要也使用同一规范，秘密字段以其哈希参与比较，不写入审计。

提交校验 declared 附件都已 received，摘要匹配，必需来源与预期条数对账。如果 manifest 已标为 partial，只有用户事先确认且 `accept_partial=true` 才能完成提交；因传输失败缺失已声明附件时，不能通过这个开关静默丢附件。需要改变材料清单时创建新的快照并重新授权，不就地修改 manifest。

首版使用有界同步提交校验，成功返回 200 和 ready；不引入后台解析大任务或通用消息队列。状态为 validating 时并发操作返回可识别的 409。失败返回明确原因，未冻结且可重试的反馈恢复 uploading。

仅 ready 且非 quarantine、非过期反馈可以被 MCP 阅读和处理。相同 submit 重试返回原成功结果，不重复产生事件；恢复接口可以确认提交结果，不授予新的写入能力。

### 7.5 错误与默认限额

| HTTP 状态 | 语义 |
| --- | --- |
| 400 | 无效字段、manifest/协议版本不支持 |
| 401/403 | 凭证缺失、失效或权限不足；不能跨反馈使用 |
| 404 | 接收功能未启用，或对该主体不可见的资源 |
| 409 | 不可变内容冲突、状态冲突、资料未上传完整、版本冲突 |
| 410 | 反馈或恢复窗口已过期，不自动重新创建 |
| 413 | 请求、文件、记录、反馈总量超限 |
| 429 | 限流或短期容量限额，返回 Retry-After |
| 503 | 私有存储不可用或暂时无法接收，禁止静默回退 |

建议初始运维默认值如下，接收方可通过受控服务配置收紧，客户端以中心返回限制为准。这些值是实现默认值，不代表无限全量承诺。

| 项目 | 默认值 |
| --- | --- |
| 截图 | 最多 5 张，每张 10 MiB，最大解码像素 25 百万 |
| 会话/日志分片 | 目标不超过 8 MiB，单文件硬上限 16 MiB |
| 单反馈 | 最多 256 个附件，总上传字节不超过 200 MiB |
| 上传 Token | 30 分钟；恢复时轮换 |
| 恢复窗口/未提交材料 | 创建后 7 天；只轮换上传 Token，不延长恢复窗口 |
| 状态回执/已提交材料 | 提交后最多 30 天；不超出材料保留期 |
| 匿名创建限流 | 每个可信客户端 IP 每小时 10 次，中心可调；不是客户身份认证 |
| 全局资料容量 | 首版默认 20 GiB，创建时按 manifest 预留；到达上限拒绝新反馈 |

为完整全量留出扩容路径：超过配额时本地保留资料并提示联系维护方调整限额，不自动截断或重复分批创建来绕过限制。最终生产额度由维护方部署时结合实际存储容量确认。

## 8. 数据模型与存储

数据库变更使用 Goose 迁移，编号取开发时实际下一个可用编号，不复用其他 P 文档的迁移号。以下为字段级设计，SQL 按仓库类型与外键风格落实；本地与中心数据库各自迁移。

### 8.1 feedback_reports

| 字段组 | 类型/约束 |
| --- | --- |
| `report_id`、显示编号 | TEXT 主键/唯一编号；ID 随机生成，编号不是授权凭证 |
| `client_feedback_id` | TEXT UNIQUE；与恢复凭证校验共同支持创建重试 |
| `description/reproduction_steps` | TEXT，有界；客户端脱敏后保存 |
| `occurred_at/snapshot_at` | TIMESTAMPTZ；来自客户端，不能作为可信安全时间 |
| `source_mode/source_id/source_claim` | anonymous/deployment，可信凭证映射来源或 NULL，自报 JSONB 独立保存 |
| `manifest/environment/consent` | 有界 JSONB，包含 schema 与授权版本 |
| `request_hash/manifest_sha256` | 不可变请求摘要/规范化 manifest 摘要 |
| `upload_status` | uploading/validating/ready/failed/expired |
| `completeness` | complete/partial；资料不完整不等于传输未完成 |
| `security_status` | normal/quarantine；安全风险不算业务处理完成 |
| `processing_status/version` | open/investigating/resolved，BIGINT 从 1 开始 |
| `assigned_to/resolved_by/resolved_agent_id` | 中心身份引用或 NULL，不引用客户本地账号 |
| `resolution_summary/public_resolution_summary/verification` | 内部结论、独立客户可见结论、验证结果 |
| `fix_commit/fixed_version/resolved_at` | 可选修复标识/版本、完成时间 |
| 凭证字段 | upload/recovery/status Token 哈希和各自 expires_at；绝不序列化为普通详情 |
| 生命周期字段 | created_at/updated_at/submitted_at/expires_at、reserved_bytes、received_bytes |

在 `(processing_status, created_at, report_id)`、`(source_id, created_at)` 建索引；查询按服务端创建时间与 ID 稳定分页。凭证失效、反馈过期检查使用中心时钟。内部结论不自动复制为 public_resolution_summary，防止泄露内部说明。

### 8.2 feedback_report_artifacts

- 联合主键 `report_id + artifact_id`，关联 feedback_reports。
- kind、display_name、content_type、declared_size_bytes、actual_size_bytes、declared_sha256、actual_sha256。
- record_count、source、part_index、记录边界等 manifest 索引。
- upload_state：declared/uploading/received/failed，uploaded_at、脱敏失败码。
- storage_profile_id、storage_key，非公开字段；已保存资料始终按原存储归属读取。

同一 report/source 的分片顺序可检查，不因跨附件分页而乱序。MCP 与后台按附件索引流式读取，不依赖重新扫描整个存储目录。

### 8.3 feedback_report_events

- event_id、report_id、event_type、before_status、after_status、version_before/version_after。
- 中心 actor_user_id、agent_id、token_id、request_id/trace_id、created_at。
- 处理结论、验证结果、重新打开原因和可选修复标识；不保存会话全文或秘密。
- idempotency_key、request_hash；同一 report + actor + operation + key 唯一。

处理更新与事件写入在同一事务内成功，失败回滚。审计与幂等先查已有同请求结果，再检查 expected_version，确保同一次成功操作重试不被误报为旧版本冲突。

### 8.4 可选部署凭证与清理任务

新增 `feedback_deployment_credentials` 保存 credential_id、可信 source_id、token_hash、状态、有效期、配额、创建/撤销审计。首版由维护方运维入口生成与撤销，不为可选功能额外建设凭证管理页面；Token 只在生成时安全交付，不在客户 Web 配置中明文分发。

新增模块内持久化对象清理任务，至少保存 profile_id/storage_key、原因、状态、重试次数及时间；删除失败可跨重启继续。避免用请求结束后的内存回调作为唯一删除保证。

### 8.5 私有存储与保留策略

首版使用中心专用本地目录，复用 FileSystemStorage 的原子写入、限额和摘要能力，不复用 SharedFiles Service、共享空间/成员权限、公开下载路由。对象键由中心生成，逻辑前缀为 `feedback/<report_id>/<artifact_id>`，本地根目录与共享网盘隔离。

后续需要 OSS 时，可复用底层已存在实现，但必须使用反馈专属私有前缀与明确的 Profile 归属；本期不提供反馈存储切换/迁移后台。存储不可用不得回退到共享网盘或其他介质。

创建时事务性预留总量，并按实际上传字节核对；单实例也必须防止并发绕过全局容量，多副本不能各自维护不一致的预留值。容量计算包含未完成、quarantine 和 ready 材料，清理后释放。

未提交材料 7 天过期；已提交材料按 submitted_at 起保留 30 天，不因 MCP 阅读或处理而自动延长。到期先禁止读取、使凭证失效，再通过任务删除对象、正文、manifest 和可识别来源。仅可保留不含正文、秘密、客户标识的最小审计/去重墓碑，默认再保留 30 天；详细备份按维护方明确的备份轮换期过期，不承诺从备份即时物理删除。

本地成功上传材料默认保留 7 天，未提交失败材料最多保留 30 天；到期前提示，手动导出的文件不由应用删除。撤回需求由维护方身份核验后按运维流程处理，首版不开放匿名删除别人资料的入口。

## 9. 管理 API 与后台页面

### 9.1 管理 API

| 接口，前缀 `/api/v1/admin/feedback` | 权限/用途 |
| --- | --- |
| `GET /reports` | read + all_feedback；按状态、来源、版本、时间、描述关键词筛选 |
| `GET /reports/:id` | read + 范围；描述、环境、manifest、截图索引、处理记录 |
| `GET /reports/:id/conversation` | read + 范围；游标分页展示会话 |
| `GET /reports/:id/logs` | read + 范围；指定附件和记录游标，支持有界查询 |
| `GET /reports/:id/screenshots/:artifactId` | read + 范围；鉴权图片预览，不暴露对象 URL |
| `GET /reports/:id/artifacts/:artifactId/content` | read + download + 范围；鉴权原始附件导出 |
| `POST /reports/:id/investigate` | investigate + 范围；open -> investigating |
| `POST /reports/:id/resolve` | resolve + 范围；open/investigating -> resolved |
| `POST /reports/:id/reopen` | reopen + 范围；resolved -> open，原因必填 |

状态更新均接收 expected_version 和 idempotency_key，调用同一反馈 Service。后台读 ready 材料；其他上传状态可显示元信息和失败原因，但禁止读取 quarantine 正文。管理写请求沿用既有 Cookie/JWT 与 CSRF/Origin 防护，不因匿名上传而跳过保护。

列表默认只查询 ready、normal、open/investigating，按创建时间倒序；页面大小默认 30，上限 100。查询关键词先只覆盖编号和描述，不构建全量日志搜索索引；日志搜索为附件内有界扫描，返回继续游标，不读取所有反馈日志做全局搜索。

### 9.2 页面与交互

管理台菜单增加“问题反馈”，图标使用已有 Lucide 图标。没有 read 权限不显示菜单，直接访问仍通过服务端与路由门禁校验。

`/admin/feedback` 列表包含：编号、描述摘要、来源与可信标识、App 版本、创建时间、资料完整性、处理状态、处理人、完成时间。顶部提供待处理/处理中/已处理/全部筛选及关键词、来源、版本、时间筛选，条件保存在 URL，返回列表保留位置与条件。列表不加载会话和日志正文。

`/admin/feedback/:id` 详情首先显示描述、截图和状态，下面使用会话/日志/环境/处理记录标签页；内容按需分页加载。截图可放大预览，日志支持附件选择、级别/Run/时间筛选及关键词定位，长内容可换行或滚动，不能撑破布局。

开始处理由中心身份确定处理人，客户端不能伪造 actor。标记已处理弹出简洁表单，内部处理结论和验证结果必填，修复提交、修复版本、客户可见结论可选；重新打开填写原因，清除当前完成时间并保留历史事件。隐藏无权限操作，仍由服务端检查。

具备加载、空列表、网络错误、附件缺失、partial、quarantine、过期、并发版本冲突和操作成功状态；不只实现静态成功页面。MCP 处理后后台通过查询失效或约 15 秒轮询更新状态；不引入 WebSocket。浏览器失焦停止轮询，详情编辑期间版本变更提示重新读取。

## 10. 独立 MCP

### 10.1 接入现有 Gateway

新增中心内置反馈适配器，建议职责包 `server/internal/feedbackmcp`，工具前缀 `feedback.`、内置 server_id 为 `feedback`。按现有内置能力路由方式注册到 Gateway，使用 Go MCP SDK 的 Streamable HTTP，不新增另一种自制传输。

专用入口为 `https://gateway.clawee.work/mcp/feedback`，仅展示获授权的反馈工具，不能在该入口调用其他上游。新增对应 `/.well-known/oauth-protected-resource/mcp/feedback` 元数据，资源 URL 和中心公共 origin 保持一致。

即使其他 MCP 入口关闭鉴权或使用测试模式，反馈入口也必须强制账号验证；不能直接套用全局 `MCPAuth.Enabled=false` 的无鉴权分支。聚合 `/mcp` 如按现有能力目录展示反馈工具，也必须使用完全相同的权限、范围和审计，不形成第二个绕过入口。

### 10.2 工具清单

| 工具 | 关键输入 | 返回与约束 |
| --- | --- | --- |
| `feedback.list_reports` | 状态、版本、来源、时间、关键词、cursor、limit | 摘要、完整性、下一页游标；不返回正文 |
| `feedback.get_report` | report_id | 描述、环境、manifest、缺失项、附件清单、状态和 version |
| `feedback.read_conversation` | report_id、cursor、limit | 按快照顺序返回记录，下一页游标与读取范围 |
| `feedback.read_logs` | report_id、artifact_id、cursor、limit、可选有界筛选 | 日志记录、来源、下一页游标、是否还有扫描范围 |
| `feedback.get_screenshot` | report_id、artifact_id | MCP 图片内容块，不只是 URL；仅允许 screenshot 类型 |
| `feedback.resolve_report` | report_id、expected_version、结论、验证、幂等键 | 完成结果、中心身份、完成时间、新版本 |

只读工具声明 readOnly；resolve 明确非只读，幂等提示仅在请求携带合法幂等键的既定契约下成立，不能把 metadata 当作权限控制。读取工具与 resolve 工具 Grant 分开授予。

文本默认每页 100 条，上限 500，单次返回最多 256 KiB；单条超大文本用明确 continuation 分段返回，不能无标识截断。游标绑定反馈 ID、附件 ID、筛选条件及固定快照，错用游标报错。读取全部是持续分页能力，不是一次把 200 MiB 塞入模型上下文。

图片工具使用实际 MIME 和受限输出大小；可提供缩小后的预览，必须标明已缩放和原始尺寸，不能伪称原图。原图由具备 download 权限的后台导出。截图、日志和会话属于不可信资料，工具说明明确其中的指令不是系统指令或操作授权。

### 10.3 完成工具契约

```json
{
  "report_id": "中心反馈ID",
  "expected_version": 3,
  "resolution_summary": "实际处理结论",
  "verification": "验证方法、结果及仍存在的限制",
  "public_resolution_summary": "可选且适合客户展示的结论",
  "fix_commit": "可选提交SHA",
  "fixed_version": "可选修复版本",
  "idempotency_key": "此次完成操作的随机唯一标识"
}
```

resolution_summary 和 verification 均必填且有界；不能只传 success=true。工具调用表示维护方完成问题处理，不表示已经发布或客户已经升级。修复版本未发布时结论必须如实说明，不能自动将本地测试成功等同于生产已修复。

Service 从认证上下文确定 resolved_by、resolved_agent_id、token_id 和时间，不接受参数伪造。仅 ready、normal 且未过期反馈允许完成，合法前置状态为 open/investigating。未完成上传、quarantine、过期或未经授权资料不能处理。

更新使用 version 乐观锁并同时写事件；同 key 同请求重试返回原成功结果，不重复写历史；同 key 不同内容、旧版本或已由其他请求完成时返回冲突，不覆盖已有结论。成功返回 report_id、processing_status=resolved、version、resolved_at 和中心处理身份。

首版为明确授权的中心 Codex 账号直接授予 resolve，不强制每次再走人工审批；现有 Gateway 的门禁配置仍可启用，启用后应正常走门禁，不能由适配器跳过。未获 resolve Grant 的 Codex 可分析资料但不能更新状态。

MCP 审计需对反馈工具单独投影：只记录报告/附件 ID、读取区间、结果数量、状态操作与脱敏错误码，不把 get/read 的返回正文完整复制进代理审计。处理结论放反馈事件表，代理审计不重复保存业务全文。

## 11. 状态与并发规则

| 状态维度 | 规则 |
| --- | --- |
| 上传 | uploading -> validating -> ready；可恢复校验失败回到 uploading，不可恢复错误为 failed；到期为 expired |
| 完整性 | complete/partial，只描述采集结果；partial 仍可以上传完成和处理完成 |
| 安全 | normal/quarantine，quarantine 优先阻断正文读取与处理 |
| 处理 | open -> investigating -> resolved，也允许 open -> resolved；resolved 仅由后台 reopen -> open |

反馈 version 仅用于业务处理状态及结论的并发更新，附件上传不让处理 version 无意义递增。开始处理、完成、重新打开均记录事件。单请求失败不能只改状态不写审计；读取后状态变化必须通过 expected_version 检查。

## 12. 安全与运维要求

- TLS、中心 origin、对象私有性和反馈专属目录是硬约束，不使用公共 CDN 分发材料。
- HTTP access log、请求/错误正文日志、代理日志、MCP 审计、客户端诊断中均遮盖所有反馈 Token 和部署头。创建 body 含秘密，禁止完整记录；补充结构化白名单日志。
- 上传与本地采集只接受已声明 ID/白名单来源，拒绝路径穿越、符号链接越界、伪造 MIME、畸形 JSON 和异常图片解码尺寸。
- 配额预留、真实大小校验、上传并发限制、临时文件回收必须一起实现，不能只检查扩展名或 declared_size。
- 限流使用可信反向代理配置解析客户端 IP，不信任任意 X-Forwarded-For。首版不新增 Redis；多副本上线前必须将限流/配额放到共享数据库或既有统一网关，不能每副本各自放宽。
- 创建超出限流返回 429；首版不引入验证码供应商，出现实际滥用时由既有边缘策略挑战或关闭匿名创建，但部署凭证上报可独立控制。
- 不接受任意远程截图 URL，不在中心代抓用户输入 URL，避免 SSRF。
- 管理 UI 对描述和日志按文本安全渲染，不执行其中 HTML、脚本、命令或链接指令。MCP 完成授权来自中心账号，不来自反馈正文。
- Codex 读取的材料可能被发送给其配置的模型服务商；由维护方保证处理账号和模型服务满足客户数据约定，后台提示和内部处理规范必须明确该边界。
- 监控只收集反馈创建/提交成功率、缺失率、上传字节、错误码、配额余量、积压、读取/处理次数、清理失败，不复制正文、截图或秘密样本。
- 源码及产物扫描、测试报告保存在仓库外并脱敏；运维配置和凭证通过 `CLAWEE_OPS_DIR` 或环境变量注入，不提交真实密钥。

## 13. 开发任务与顺序

按以下顺序实施，每阶段均以可验证交付物结束，不另创建规划文档或新分支。

| 顺序 | 开发任务 | 验证出口 |
| --- | --- | --- |
| 1 | 明确协议类型、规范化 manifest、Go/TS 测试向量、状态与错误码 | 相同资料摘要一致；无效协议样例被拒绝 |
| 2 | 中心迁移、Memory/Postgres Store、反馈 Service、专属本地存储和配额/清理 | 新库/已有库迁移，事务/补偿/过期测试通过 |
| 3 | 匿名创建、恢复、上传、提交、查询回执与部署凭证运维入口 | 无账号可上报，但任何上报凭证均无法读取正文或处理 |
| 4 | RBAC、管理 API、列表/详情/处理页面 | 可定位未处理问题；状态并发和无权限验证通过 |
| 5 | 内置 MCP 适配器、专属端点、审计投影和 resolve 工具 | 授权 Codex 可读截图、分页资料并完成；匿名/只读账号失败 |
| 6 | 本地 SQLite 队列、Thread 全量采集、关联日志、Desktop Bridge 和 Web 反馈入口 | 长会话/Runtime 轮换/运行中快照/重启续传不漏采或明确 partial |
| 7 | 端到端、限额/隐私测试、客户端预检、上线配置核对 | 在隔离环境完成闭环，不使用客户或中心生产数据试错 |

建议新增职责位置为 `client/apps/daemon/src/feedback/`、本地 `api/routes.feedback.ts`、Web 会话反馈 feature、`server/internal/feedback/`、`server/internal/feedbackmcp/`、管理台 `lib/feedback-admin-api.ts` 与反馈页面。文件名按实际目录习惯确定；不要为单次需要抽离通用任务平台、上传框架或重构 sharedfiles 包。

## 14. 验收与测试矩阵

| 场景 | 必须得到的结果 |
| --- | --- |
| 客户 Gateway 与中心不同域名 | 请求只发往中心，没有客户 Authorization/Cookie/模型秘密 |
| 客户实例未启用接收 | 匿名上报和反馈 MCP 均不可用；核心工作台不受影响 |
| 客户禁用外部反馈 | 不能采集外传，待发送队列暂停；不改接收方绕过策略 |
| 无中心账号 | 可匿名创建并提交，不能获取列表、正文、截图或管理状态 |
| 跨反馈凭证/猜测 ID | 上传、恢复、状态查询全部拒绝，不能枚举他人内容 |
| 创建/提交响应丢失 | 使用同 ID/恢复证明找到原反馈，不重复建单或重新开放写入 |
| 长会话超过默认列表数/多个 Runtime Thread | 完整遍历固定集合，无 50/10,000 条隐式上限；不能导出则标记缺失 |
| 运行中快照/日志 flush 超时 | 不停止任务，保存真实 watermark；不确定来源为 partial |
| 历史日志缺失/源输出被截断/daemon 不可用 | 明确缺失原因；本地应急导出标记 partial，不伪造完整上传 |
| 相同工具输出重复出现 | 保留不同真实事件，展示去重不删除事实材料 |
| Token 与 prompt | 消息正文可排障，秘密遮盖；原诊断 prompt 脱敏契约不变 |
| 断网/重启/Token 过期 | 队列与材料保留，续传跳过已收到附件，不超过恢复期限 |
| 伪造类型/路径/过大图片/超额并发 | 拒绝且无越界、内存失控或配额绕过，失败对象可回收 |
| Storage/数据库失败 | 不静默回退，孤立对象持久化补偿，业务状态不虚报 ready |
| 后台列表与详情 | 筛选、返回位置、截图、会话/日志分页、partial 与失败状态可用 |
| MCP 截图/长日志 | 实际图片内容块可读，资料可分页遍历，无无标识截断 |
| MCP 查询账号尝试 resolve | 权限拒绝；普通客户凭据和匿名凭据也全部拒绝 |
| MCP 成功 resolve | 状态、结论、真实身份、时间、version 与审计同事务更新，后台及时显示 |
| 相同完成请求重复/两个处理者并发 | 同 key 同请求幂等；不同请求旧版本冲突，不覆盖结论 |
| 后台 reopen | 原完成结论保留在事件，当前状态为 open，操作原因和身份可查 |
| 回执状态查询 | 不返回内部结论、会话、截图、客户身份或存储路径 |
| quarantine/到期 | 所有正文渠道受阻断，Token 失效；资料及索引可清理，失败可重试 |
| 反馈正文含恶意指令 | UI 不执行，MCP 不把内容当作处理授权或系统指令 |

服务端单元/HTTP/MCP 测试覆盖上述权限、事务、边界和协议，集成测试仅使用隔离数据库和临时存储。前端测试覆盖列表、详情、授权、状态更新、冲突与错误场景，检查窄窗口长文本和日志不会溢出。

开发时先查看根目录与所属工作区 package.json，使用实际已有测试/类型检查/构建命令，不把本文当作新脚本已经存在的声明。修改客户端可执行代码后提交前必须运行客户端 `desktop:preflight:local`，验证测试、类型、实际 App 打包和内嵌 Web 哈希；未通过不得宣称可发布。仅保存本文不要求打包客户端。

## 15. 上线检查与完成定义

维护方上线时确认中心反馈接收显式启用、私有目录/容量、HTTPS 与反向代理请求大小/超时、可信代理限流、清理任务、中心人员权限、MCP 账号/Agent 绑定、只读与完成工具 Grant 均正确。默认限额可调整，但不得降低客户端完整性判断标准。

先在隔离环境验证同一版本桌面端到中心的提交、后台查看、MCP 阅读、处理完成、后台刷新闭环，再按既有发布门禁上线。正式发布仍遵循仓库版本检查、本地预检、已推送 SHA 的远端 Release Preflight 与 Tag 检查，不使用远端发布反复试错。

完成定义：客户无中心账号也能主动提交当前会话反馈；资料要么在既定范围完整，要么明确 partial；客户凭据不外泄；维护方后台可快速查看并管理是否已处理；授权 Codex 可以读取同一资料并通过 resolve_report 更新真实处理状态；所有读取、状态变更和资料清理均满足本方案权限与审计要求。
