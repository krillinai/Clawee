# 工作流初版讨论稿

> 状态：讨论中  
> 用途：用于客户调研和方案讨论，不代表最终设计或当前已实现能力。

## 讨论目标

初版关注通用工作流基础能力：在 Gateway 管理控制台的“工作台”中可视化编排流程节点，由 Gateway 管理运行实例和节点任务；客户端 APP 通过接口查询参与的实例、拉取本人负责的审批或 Agent 执行任务，并查看执行过程。

以下内容工作流仅用于说明如何使用基础能力，不是初版必须配出的业务流程：

```text
热点发现 -> 选题判断 -> 脚本生成 -> 人工审核 -> 发布任务 -> 数据回流
```

初版完成基础能力后，再根据实际业务将这个案例配置出来。数据回流属于独立的后续任务，不纳入初版工作流能力的验收范围。

## 核心概念与边界

- **工作流模板**：静态的流程配置，定义节点顺序、节点类型、负责人和执行所需配置；本身不代表一次执行。
- **工作流实例**：依据模板发起的一次具体运行，记录当前节点、参与人、整体状态和各节点的执行记录。同一模板可产生多个实例；已启动实例按启动时的模板配置执行，不随模板后续编辑而改变。
- **节点任务**：实例推进到某个节点时产生的具体待办，关联该实例、节点和负责人。审批节点产生审批任务，Agent 执行节点产生 Agent 任务；任务完成后写回输入、输出和结果，由工作流服务决定下一步。

本地 Agent 执行仍由客户端及其本地 daemon/Runtime 负责；Gateway 保存企业侧模板、实例、任务和授权审计，不把本地执行能力或本地模型凭据迁入服务端。

## 初版方案

初步将 Workflow Service 作为 Gateway 内部模块提供，复用现有账号、权限、审计及 API 边界；这是初版的部署建议，不预先拆成独立服务。它负责模板与实例的持久化、节点任务分派、状态推进以及结果记录，是流程状态的唯一来源。客户端只通过 Gateway 接口获取任务、提交结果，不能自行跳过节点或修改实例整体状态。

管理控制台中的“工作台”用于管理员创建、编辑和查看工作流模板，查看与操作工作流实例。客户端 APP 面向参与者：查询当前用户参与的运行中实例，查看实例详情，并处理当前分配给自己的节点任务。初版不建设内容平台、素材平台或数据分析平台。

## 初版节点与编排

只考虑两类节点：

- **审批节点**：指定负责人，通过客户端领取或打开待办，查看输入后批准或驳回，并记录意见与结果。
- **Agent 执行节点**：指定负责执行的用户及任务配置；该用户的客户端通过接口拉取待办，交由本地 Agent 执行，向 Gateway 回传输出或失败结果。具体业务动作由任务配置及已有能力承载，不单设发布节点。

工作台初版提供可视化流程编辑器，支持添加两类节点、调整串行顺序、配置节点负责人和任务内容、保存并查看流程。保存或启动前校验节点顺序及必要配置。初版只支持固定顺序的串行流程，不支持分支、并行、循环、子工作流或运行中动态改图。图形编辑和持久化以同一份模板配置为准。

一个实例一次推进一个节点；前序节点的结果可作为后序任务的输入。每个节点任务独立记录输入、输出、状态和处理人，Agent 执行不依赖长期保持的聊天上下文。审批驳回后实例结束；执行失败时保留失败信息供有权限的管理员处理，不默认自动跳过。

## 参与者与操作界面

- **客户端列表**：通过 Gateway 接口按当前用户身份查询其参与的运行中工作流实例，包括分配给自己的节点以及已处理过的实例；展示模板名称、实例状态、当前节点和本人待办状态。
- **客户端详情**：展示当前节点、节点顺序及各节点已产生的输入、输出和处理结果。当前节点由本人负责时，可以进入对应审批或 Agent 任务并提交结果；不是当前负责人但参与过该实例时，可以查看前后节点已有的工作记录，未执行节点不显示尚不存在的输出。查看仍受实例参与者权限和数据权限约束。
- **管理控制台**：管理员在工作台管理模板、查看实例进度与各节点记录，并对有权限的实例执行必要的管理操作。普通参与者不能通过客户端获得管理员操作权限。

审批与 Agent 任务均由 Gateway 按身份提供待办查询和详情接口，客户端不依赖管理控制台页面取数。任务提交时校验实例当前节点及负责人，避免同一节点被重复处理；服务重启后仍能从已保存的实例与任务状态恢复。

## 初版范围与验收

1. 管理员能在工作台通过可视化编辑器配置、保存两类节点组成的串行模板，并据此发起实例；实例保留启动时的配置。
2. Gateway 能依节点顺序产生审批或 Agent 任务，记录输入、输出、负责人及结果，并在任务完成后推进实例。
3. 客户端能查询本人参与的运行中实例和待办；本人负责当前节点时能处理任务，参与过但不负责当前节点时能查看有权限的已有节点记录。
4. 管理员能在管理控制台查看工作流模板和实例，定位当前节点，并执行初版确定的管理操作。

初版不包含具体内容案例的完整配置、实际发布连接器、数据回流、自动返工、多级会签和复杂审批策略，也不建设通用表达式语言。发布任务如需纳入后续案例，须先确认由 Agent 调用受控能力，还是由人工完成；初版不为这个案例预设第三类节点。

## 待确认问题

- 模板由谁发起为实例、各节点负责人是模板固定指定还是启动时指定，以及允许哪些管理员操作（终止、重试等）。
- Agent 任务在客户端的领取、执行与结果回传如何对接现有本地任务/会话能力；客户端离线或任务执行失败时的处理规则。
- 参与者对其他节点输入、输出的可见范围，尤其是敏感内容的权限边界。
- 具体内容案例中，发布任务采用人工处理还是受控 Agent 能力；数据回流作为独立后续任务如何关联原实例。

以上细节需要结合现有接口和客户工作方式进一步确定，不影响初版以通用编排、任务处理和实例查看为核心的方向。
