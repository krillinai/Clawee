# P3 客户端发布配置与下载分发改造开发计划

## 1. 背景与目标

当前 `/downloads` 页面依赖服务端启动配置，下载地址和标准包地址存在固定兜底逻辑，管理员无法在管理后台更新。该方案将客户端发布配置纳入 Gateway 管理，并依据 COS 发布目录协议中的 `catalog/stable/latest.json` 动态生成下载链接。

目标：

- 在管理后台“系统管理”下提供“客户端发布”配置页。
- 管理员可以配置 Gateway 服务端地址和稳定版 `latest.json` 地址。
- 下载页面展示已保存的服务端地址，并展示 `latest.json` 中的企业客户端安装包。
- 删除“企业客户端”和“开源标准包”两个容易产生歧义的并列概念，保留单一的企业客户端下载区块。
- 配置持久化到 Gateway 数据库，重启服务后仍然有效。

## 2. 范围与边界

### 2.1 本次包含

- PostgreSQL 配置表、迁移和默认配置。
- 客户端发布配置服务及管理 API。
- `latest.json` 的服务端读取、校验和平台包解析。
- 客户端发布配置页、菜单项和 RBAC 权限。
- `/downloads` 页面改造及相关测试。

### 2.2 本次不包含

- 修改 COS 发布工作流或 `latest.json` 生成格式。
- 在管理后台上传安装包。
- 支持稳定版以外的 prerelease 渠道。
- 增加 Linux Desktop、Windows arm64 或新的安装包类型。

## 3. 通用后台配置模型

不为客户端发布单独创建 `client_download_settings` 表。本次新增通用 `platform_settings` 表，后续平台外观、登录策略、通知等后台配置均按命名空间复用：

```sql
CREATE TABLE platform_settings (
    namespace TEXT NOT NULL,
    config_key TEXT NOT NULL,
    config_value JSONB NOT NULL,
    version BIGINT NOT NULL DEFAULT 1,
    updated_by TEXT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL,
    updated_at TIMESTAMPTZ NOT NULL,
    PRIMARY KEY (namespace, config_key)
);
```

客户端发布使用 `client_downloads/default` 配置项：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `namespace` | `TEXT` | 固定为 `client_downloads` |
| `config_key` | `TEXT` | 固定为 `default` |
| `config_value` | `JSONB` | 包含 `gateway_url` 和 `catalog_url` |
| `version` | `BIGINT` | 乐观锁版本号 |
| `updated_by` | `TEXT` | 最近修改人 |
| `created_at` | `TIMESTAMPTZ` | 创建时间 |
| `updated_at` | `TIMESTAMPTZ` | 修改时间 |

默认值：

- `gateway_url`：当前 Gateway 的 origin。
- `catalog_url`：`https://cdn.krillinai.com/clawee/catalog/stable/latest.json`。

默认值只用于首次初始化或数据库尚未配置时的兜底；管理员保存后以数据库值为准。通用表不允许业务代码直接操作，必须由模块 Service 负责类型转换和校验。

## 4. 后端开发任务

### 4.1 数据库与存储

1. 新增 Goose 迁移，创建 `platform_settings` 通用表。
2. 新增通用 `SettingsStore`，按命名空间和 key 读写 JSON 配置，并支持 `version` 乐观锁。
3. 在 `internal/clientdownloads`（或同等职责包）新增客户端发布配置类型、校验逻辑和 Service，底层使用 `SettingsStore`。
3. 校验 `gateway_url` 为合法 HTTPS origin；本机回环地址允许 HTTP。
4. 校验 `catalog_url` 为合法 HTTPS URL，禁止用户信息、片段和不必要的查询参数。
5. 接入 `server.Options` 和路由初始化，保持无数据库或测试环境下可使用 MemoryStore。

### 4.2 管理 API

新增接口：

```text
GET /api/v1/admin/client-downloads
PUT /api/v1/admin/client-downloads
```

要求：

- 使用现有 Admin JWT、统一错误响应和 `requirePermission` 中间件。
- GET 返回服务端地址、清单地址、更新时间和最近一次清单状态（可选）。
- PUT 接收 `gateway_url`、`catalog_url`，校验通过后保存并记录 `updated_by`。
- 返回 `no-store`，避免管理配置被浏览器缓存。

### 4.3 公共下载 API

继续提供：

```text
GET /api/v1/public/client-downloads
```

改为动态读取客户端发布配置，并服务端请求 `catalog_url`。解析 `latest.json` 时：

- 只接受 `artifacts[]` 中的桌面客户端安装包。
- 映射 macOS arm64、macOS x64、Windows x64。
- 使用 `downloadUrl`、版本、SHA256 和签名字段。
- 对缺失字段、未知平台、非法 URL、超大响应和无效 JSON 返回可识别错误。
- 使用短时内存缓存或等效机制，避免每次打开下载页都重复请求 CDN。
- CDN 或清单不可用时返回明确的服务不可用响应，不返回过期或固定写死的下载地址。

## 5. RBAC 与管理台开发任务

### 5.1 权限

新增权限：

- `console:client_downloads:read`：查看客户端发布配置。
- `console:client_downloads:update`：修改客户端发布配置。

将权限加入权限目录、系统管理员默认权限和相关测试。

### 5.2 菜单与路由

在管理中心“系统管理”分组增加：

- 菜单名称：`客户端发布`
- 路由：`/admin/client-downloads`
- 图标：Lucide `Download` 或 `PackageOpen`

无查看权限时隐藏菜单；直接访问路由时由现有权限门禁返回无权限状态。

### 5.3 配置页面

页面沿用现有 `PageShell`、`PageHeader`、表单控件和提示组件，包含：

- 服务端地址输入框。
- 稳定版 `latest.json` 地址输入框。
- 保存按钮，仅在拥有 update 权限时显示或启用。
- 加载、保存、校验失败和成功提示。
- 当前清单读取状态及平台包摘要（用于管理员确认配置有效）。

前端 API 单独维护在 `server/web/src/lib/client-downloads-admin-api.ts`，不复用公共下载 API 的类型。

## 6. 下载页面改造

`/downloads` 页面调整为：

- 服务端地址来自公共 API 返回值，保留复制按钮。
- 只保留一个“企业客户端下载”区块。
- 展示 macOS Apple Silicon、macOS Intel、Windows x64 的企业安装包。
- 下载链接、版本、签名和 SHA256 全部来自解析后的 `latest.json`。
- 删除“开源标准包”区块、`standardClientDownloadURL` 和标准包相关文案。
- 清单为空、请求失败或解析失败时显示清晰状态，不伪造可用下载链接。

## 7. 验收标准

### 功能验收

- 系统管理员能在“系统管理 → 客户端发布”打开配置页并保存两项配置。
- 普通用户不能读取或修改管理配置。
- Gateway 重启后配置仍存在。
- 修改 `latest.json` 地址后，下载页使用新地址返回的安装包。
- 下载页不再出现“开源标准包”或固定 GitHub 标准包链接。
- 三个平台的下载链接与 `latest.json` 中的 `artifacts[].downloadUrl` 一致。
- 清单地址不可用时，页面展示错误状态且不展示旧的硬编码链接。

### 工程验收

- 数据库迁移可在空库和已有库上执行及回滚。
- Go 单元测试覆盖 URL 校验、JSON 解析、缓存失效和错误映射。
- HTTP 测试覆盖权限、读写接口和公共下载接口。
- React 测试覆盖配置页加载/保存、无权限状态和下载页平台包展示。
- `server/web` 的 TypeScript 检查、构建和现有测试通过。

## 8. 实施顺序

1. 数据库迁移、通用 SettingsStore、客户端发布配置类型和 Service。
2. RBAC 权限目录与管理 API。
3. 公共下载 API 的 `latest.json` 解析和缓存。
4. 管理后台菜单、路由和配置页。
5. 下载页精简与公共接口适配。
6. 补齐测试，执行服务端测试和前端构建。

## 9. 风险与处理

- **CDN 短时不可用**：公共 API 返回明确错误，管理页提供读取状态，避免展示不可信链接。
- **`latest.json` 格式变化**：解析器采用字段校验并拒绝未知或不完整包，测试固定协议样例。
- **配置错误导致客户端无法连接**：保存前校验 Gateway origin，页面明确说明不得填写 `/api` 或 `/mcp`。
- **缓存导致发布延迟**：只使用短时缓存，并设置公共响应为 `no-cache` 或短缓存。
