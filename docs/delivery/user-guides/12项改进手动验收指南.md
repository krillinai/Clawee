# Clawee 12 项改进手动验收指南

本指南用于 12 项通用功能的手动回归检查，编号为 T01–T12。实际版本、结果、证据及复测记录另行登记。普通员工获授权的普通 Skill 可下载安装，A2A 专属 Skill 仅在受控服务器安装执行，服务端任务成果的下载不包含专属 Skill 源包。

## 验收准备与顺序

- 使用测试 Gateway 和本地测试数据，记录客户端版本、服务端版本及目标平台；更新测试前备份本地数据，不使用生产实例。
- 准备管理员、员工甲、员工乙、无授权员工丙；建立包含甲、乙的测试角色。准备一个测试技能空间、一个有新旧版本的 Skill、一个“执行 → 审批 → 执行”的工作流，以及两个可区分的测试服务器。
- 建议顺序：先验 T12、T09、T10、T11，确认登录与模型可用；再验 T01、T02、T06；然后连测 T03、T04、T05、T07；最后验 T08。
- 每项至少测一次正常流程和一次异常流程。保留关键截图、任务或审批编号；结果标记“通过 / 不通过 / 未测”，缺少环境或入口时记“未测”，不视为通过。

## T01 角色管理与技能空间授权

**操作建议：** 同一技能空间同时授权员工甲和测试角色，检查甲、乙可访问而丙不可访问；撤掉角色授权，再撤掉甲的直接授权。工作流节点同时指定甲和该角色，甲、乙各自打开同一待办并先后提交。Skill 审核也使用这一重叠配置，由甲、乙分别审批。

**验收标准：** 账户和角色授权取并集且不重复计数；撤掉角色后甲的直接授权仍有效、乙失去访问权，撤掉全部授权后甲也不可访问。工作流任一负责人完成后只流转一次；Skill 必须全部去重后的评审人通过才通过，单人通过不能提前完成。原有仅账户授权仍可正常使用。

## T02 服务端 Agent 成果预览与下载

**操作建议：** 在服务端 Runtime 任务中生成中文名文本、受支持的预览文件及不支持预览的文件，检查客户端成果列表、预览和下载；重开会话再次查看。让技术人员辅助验证无 Runtime 授权访问及越界路径请求。

**验收标准：** 成果与当前任务对应，文件名和内容正确；支持的格式能预览，不支持的格式仍能下载，下载后文件可正常打开。无 Runtime 授权和越界访问被拒绝，错误信息不暴露服务端本地路径。沿用 Runtime 授权边界，不以“不同账户必须互相隔离成果”作为本项标准。

## T03 工作流创建、定时触发与流转完善

**操作建议：** 后台创建并手动发起测试工作流，逐节点执行、审批，另开实例测试驳回。设置几分钟后触发的定时计划，核对时区、启停和触发记录；让执行客户端离线或节点失败，再恢复并重试。同一处理动作连续点击两次。

**验收标准：** 手动和定时发起均生成正确实例与待办；计划按配置时区触发，停用后不再新增实例。节点按顺序流转，驳回走约定分支；客户端离线或执行失败时不自动跳过节点。恢复或重试后可继续，重复触发和提交不重复建实例或变更状态。定时触发只创建实例与待办，不要求离线客户端自动执行。

## T04 Skill 人工评分与结果汇总

**操作建议：** 甲、乙对同一 Skill 版本填写不同的四维评分和意见；先尝试漏填、0、6及小数，再完成有效评分。全部通过后，按页面评分标准手工核对汇总；随后上传新版本并查看评分记录。

**验收标准：** 四维标准说明可查看；通过时四维必填且只能为 1–5 的整数，无效分值不能提交。每位评审人的原始分值、意见均保留，通过后的各维汇总及总分与公示规则一致。评分绑定对应版本，新版本不继承旧内容评分。

## T05 统一审批中心

**操作建议：** 同时发起 Skill 审核和工作流审批；用甲、乙、丙分别查看“待办、已办、我发起”，切换类型和状态筛选。处理一条待办后回到列表并查看业务详情；在另一窗口保留旧待办，处理完成后再次提交。

**验收标准：** 两类审批可统一查找，筛选结果正确；各账户只能查看和处理获权内容。“我发起”归属正确，处理后待办、已办和业务详情状态同步，处理人、意见及时间可追溯。已被处理或过期的待办不能再次生效，不重复流转。

## T06 服务端 Agent 自动安装授权 Skill

**操作建议：** 用已授权且已发布的 Skill 发起服务端任务，不手动安装；再执行一次相同版本。分别测试无授权 Skill、未发布版本，并在成功安装后撤掉全部授权，再发起新任务。

**验收标准：** 获权的已发布 Skill 在任务准备阶段自动安装并能实际调用，安装记录可核对版本和摘要；相同版本不重复安装。无授权及未发布版本被拒绝，撤权后不能借旧安装继续调用。摘要不匹配的包不能进入执行；该异常由技术人员在测试环境辅助构造。

## T07 Skill AI 审核工作流

**操作建议：** 提交材料完整的 Skill，依次查看材料检查、AI 报告与证据、人工评分及审批，再验证发布。另测缺少必要材料和 AI 服务失败；即使 AI 给出正面结论，也先保留一位人工评审未通过。

**验收标准：** 提交后进入审核流程，各阶段及待办可追踪；人工可查看对应版本的 AI 报告和证据，并填写评分。材料异常或 AI 失败有明确状态和人工处理入口，不误判通过或误发布。AI 结论不代替人工决定，全部必要人工审批通过后才可进入发布环节。

## T08 客户端自动更新闭环

**操作建议：** 用真实旧版本保留模型设置、服务器地址和历史会话，检查更新，观察下载进度并完成安装、重启。另测下载中断、无效更新包，以及有任务运行时发起更新；官方包与客户包分别验证，只验实际支持的平台。

**验收标准：** 旧版本可升级到目标版本，版本号正确，设置、会话和本地数据保留；进度及失败提示明确。下载失败或包校验失败不替换旧应用，旧版仍可启动。运行中任务的阻止、等待或确认行为明确，不静默中断或丢失任务。官方包与客户包不串用更新源或安装包。

## T09 模型配置增加 trim

**操作建议：** 将有效模型地址、模型名及本机密钥等文本字段加上首尾空格、换行或制表符后粘贴，检测、保存，再发起真实任务；另用合法且含内部字符的配置对照检查。

**验收标准：** 约定需要 trim 的字段清除首尾空白，检测、保存与实际调用使用一致配置，原本有效的配置可正常执行。字段内部有效字符不被删除或改写。不把“删除所有不可见字符”作为标准，超出 trim 的字符按已确认规则验证。

## T10 客户端模型异步检测与设置体验

**操作建议：** 首次配置后重启客户端，用测试网络延迟或不可用模型观察启动；进入“设置 → AI模型配置”，检查本机已保存密钥的显示与隐藏。分别检测有效和无效配置，并只修改表单、检测而不保存。

**验收标准：** 首次配置保留必要校验，后续启动不等待模型检测结束即可进入工作台；不可用时有明确提示及重新检测入口。已保存的本机密钥默认隐藏，可主动查看并再次隐藏；平台托管密钥不回显。检测按钮有检测中、成功和失败反馈，与启动检测判断一致；单独检测不保存或切换当前配置，日志和结果不包含完整密钥。

## T11 品牌高亮色配置与员工自定义

**操作建议：** 无后台下发配置时检查默认色；管理员下发另一种有效 HEX 色，员工刷新或重启后查看高亮区域。员工在“设置 → 常规”自定义颜色，重启，再修改后台颜色，最后切回“跟随品牌”。

**验收标准：** 无下发配置时使用 `#F2E9EA`，后台配置正确下发并用于客户端高亮区域。员工自定义可保存且重启后保留，优先于后台默认；切回“跟随品牌”后使用后台颜色。高亮文字、选中项及按钮保持可辨识，非法 HEX 值不能保存。

## T12 登录与设置页多服务器地址管理

**操作建议：** 用全新测试配置启动，在登录页填写并保存服务器；通过下拉列表添加第二个地址、编辑当前地址并切换。登录后在设置页增删改其他地址，保存并重启；另测非法地址和保存失败。退出登录且运行任务结束后，再修改或切换当前服务器。

**验收标准：** 无配置时可直接填写、保存并登录；地址列表和当前选择重启后恢复。下拉中的添加、编辑动作不误触发切换；登录后当前服务器只读，保存其他地址不影响当前登录态。修改或切换当前服务器遵守退出登录与任务结束约束；非法地址被拒绝，保存失败保留原配置。

## 优先判定不通过的情况

出现以下任一问题，对应项不通过：越权访问或撤权失效；重复生成实例或重复流转；未完成必要人工审批即发布；失败时跳过节点；更新造成数据丢失或错误替换旧应用；服务器编辑误切换当前登录态；完整密钥泄漏。

其余问题按对应项标准记录，不用自动化测试通过替代人工验收。建议记录格式：`编号｜通过/不通过/未测｜版本与账号｜操作及实际结果｜截图/任务/审批编号`。
