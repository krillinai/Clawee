# 钉钉审批接入配置

本文适用于已有钉钉登录应用的 Clawee Ubuntu Gateway，为技能空间启用钉钉 OA 审批。复用原应用的 Client ID、Client Secret 和已绑定的员工身份；不要新建应用或修改登录回调地址。钉钉审批通过后仍须由具有发布权限的人在 Clawee 手动发布版本。

## 1. 配置文件

Ubuntu 部署使用仓库外 `$CLAWEE_OPS_DIR/configs/config.ubuntu.yaml` 作为配置来源，线上生效文件为 `/home/ubuntu/work/clawee/configs/config.ubuntu.yaml`。不要误改通用的 `$CLAWEE_OPS_DIR/configs/config.yaml`；`server/scripts/deploy-release.sh ubuntu` 上传的是 Ubuntu 专用配置。

在现有 `dingtalk:` 段中保留已配置的 `enabled: true`、`client_id`、`client_secret`、`redirect_url`、`provider_key` 等字段，只增加以下三项：

```yaml
dingtalk:
  oa_enabled: true
  oa_event_token: "钉钉事件回调设置中的 Token"
  oa_encoding_aes_key: "钉钉事件回调设置中的 EncodingAESKey"
```

两项密钥必须与钉钉后台一致。`oa_encoding_aes_key` 必须是有效的 43 字符 EncodingAESKey；Gateway 在启用 OA 时校验登录应用凭据、Token 和密钥。生产密钥只保存在仓库外的私有配置中，不要写入源码或提交到 Git。技能空间的审批模板 `processCode` 不填在此文件中，而是在管理台按空间设置。

## 2. 钉钉后台配置

钉钉后台的菜单名称可能随版本调整，以页面实际显示为准。操作时始终选择与 Clawee 登录使用同一个企业内部应用。

### 2.1 应用权限

进入**钉钉开放平台 → 应用开发 → 企业内部应用 → 现有 Clawee 应用 → 权限管理**，查找并申请发起 OA 审批实例、查询审批实例所需的权限；同时确认应用能订阅审批实例事件。核实目标审批模板允许该应用发起，不要只检查钉钉登录权限。

### 2.2 审批模板

由审批管理员进入**钉钉管理后台 → 工作台 → OA 审批 → 审批管理**，新建或选择测试审批流程，设置审批节点和发起人范围。发起人范围须覆盖将在 Clawee 上传版本的员工。

模板表单准备以下五个字段，名称与大小写须与 Gateway 发送的字段一致，字段值均按文本接收：

| 字段名称 | 内容 |
| --- | --- |
| `Skill 名称` | Skill 名称 |
| `版本` | 版本号 |
| `变更说明` | 上传时填写的变更说明 |
| `包 SHA-256` | 上传包摘要 |
| `Clawee 详情` | 需要 Clawee 权限才能访问的详情页地址 |

发布流程后记录模板的 `processCode`（审批模板唯一标识，不是模板显示名称）。具体字段类型、模板调用权限和 `processCode` 的取得方式须在目标企业用测试流程联调确认。

### 2.3 事件订阅

返回**钉钉开放平台 → 应用开发 → 企业内部应用 → 现有 Clawee 应用 → 事件订阅／事件与回调**，选择 **HTTP 回调**，订阅审批实例状态变更事件 `bpms_instance_change`（审批实例开始、结束、终止、删除）。在回调设置中取得 `Token` 与 `EncodingAESKey`，填入第 1 节的配置文件。

当前 Ubuntu 环境的事件回调地址为：

```text
https://gateway.clawee.work/api/v1/integrations/dingtalk/skill-approval/callback
```

这是独立的 OA 事件入口，**不是**已有的 `/api/v1/auth/dingtalk/callback` 登录回跳地址。若该应用已有事件回调地址，不要直接覆盖原回调；先确认钉钉应用的回调限制，并在现有统一入口按事件分发到新接口。回调地址须从钉钉服务端访问到 Gateway，且 Token 与 EncodingAESKey 必须与 Gateway 配置一致。

## 3. 部署与 Clawee 空间设置

1. 先完成生产数据库备份、发布验证以及钉钉模板和回调密钥准备。不要只修改线上 YAML 就开始联调：还需部署包含 OA 路由的新 Gateway 和 `00062_skill_external_approval.sql` 数据库迁移。
2. 按现有发布流程执行 `server/scripts/deploy-release.sh ubuntu`。该脚本会上传 Ubuntu 专用配置、执行数据库迁移并重启 `claw-gateway.service`；执行前检查发布产物、目标数据库和服务停机窗口。脚本不会创建钉钉模板或设置事件订阅。
3. Gateway 就绪后，在钉钉后台保存第 2.3 节的事件回调配置。若钉钉保存时要求校验回调，应确保新服务已启动且可从公网访问。
4. 在 Clawee 管理台进入**技能中心 → 技能空间 → 目标空间“设置”**，将审批方式改为**钉钉 OA**，填写该模板的 `processCode` 并保存。只有具备空间管理权限的人可以修改。
5. 让已绑定钉钉身份的上传者上传一个人工版本并点击**提交钉钉审批**。在钉钉完成审批后确认 Clawee 中的状态；审批通过后由具有发布权限的人手动**设为当前版本**。Git 同步版本不提交 OA。

若审批已结束但 Clawee 未收到回调，具有发布权限的管理员可在 Skill 详情中使用**同步审批结果**。提交状态不确定时先到钉钉核实实例，再使用**核对申请**；不要盲目重提。

接口与流程依据见[技能空间接入外部审批方案](../v1/P5-技能空间接入外部审批方案设计.md)；Gateway 基础部署及迁移注意事项见[运维部署指南](./operations-guide.md)。
