# 客户服务器控制通用客户端更新

## 渠道与数据边界

客户端的更新能力不依赖包内客户标记。可分发的 `dist` / `release` 包不注入客户 Gateway，不生成 `deployment/customer-update.json` 或客户专属更新清单。仅受控 `dir` 验证构建允许使用原有企业测试配置；不得将该测试 App 当作客户分发包。

用户在运行时配置客户服务器，地址和凭据保存在用户设备。桌面主进程直接从本机 `config.toml` 读取当前 HTTPS Gateway，使用公开更新元信息和下载接口，不需要登录、账号或 Agent 身份验证，也不依赖 daemon 和共享 Web 启动成功。企业令牌不离开 daemon，也不发送给更新包下载站；历史服务器列表不参与更新决策。

只有当前更新服务器地址变化或被移除时，才清除旧来源的批准和下载状态，并检查新来源。退出登录、切换账号、会话过期及续期不取消同源更新。配置缺失、无效或使用 HTTP 时不访问更新源；服务器部署模式不执行桌面安装。主进程不接受渲染层传入的下载 URL 或更新渠道。

## 后台操作

1. GitHub CI 正常发布稳定 Tag，上传各平台通用包、`release.json`、更新 YML 与稳定版本目录；不设置客户 Gateway 构建变量。
2. 在 `/admin/client-downloads` 配置稳定版 `latest.json` 下载入口。更新版本列表从同目录的 `versions.json` 读取。
3. 勾选“启用客户更新”，选择已发布目标版本，核对平台包及不可用平台提示，填写更新说明，点击“保存更新配置”并确认。
4. 服务端从目标版本的不可变目录读取发布资料，校验更新 YML 的 SHA256、目标版本、更新包 URL、大小及 SHA512，再保存批准快照。macOS 原生更新使用已有 ZIP，Windows 使用已有 NSIS EXE；不重新打包客户产物。
5. 后续正式发布不自动改变客户的目标版本。停用后不再提供快照与对应 feed；已安装版本不会回退。同一版本可停用后重新启用，复用原批准包，修订号持续递增。

更新配置沿用设置存储、现有 RBAC 与 CAS 修订控制，不需要手工修改数据库。旧清单发布接口保留兼容，新的管理页面只提交启用状态、版本、说明与 `expected_revision`。

## 客户端执行

桌面启动时即检查更新，此后每十五分钟复查；每三十秒检查本机更新源是否改变及是否需要推进下载、重试或安装。网络恢复和系统唤醒会触发复查，仍可在设置中手动检查。检查失败按三十秒起指数退避，单次间隔最长十五分钟，恢复后继续自动升级。只处理目标版本严格高于 `app.getVersion()` 且有当前平台包的批准快照，不降级。

发现更新后后台下载、检查摘要、平台校验、解压、空间和权限。每 30 秒只推进仍获准自动执行的更新；这不是安装失败后的无限重试。共享 Web 每十秒报告编辑状态，输入、键盘和点击立即更新活动时间；存活的工作台仍要求未保存文件和草稿保存失败已处理、活动状态新鲜、连续 60 秒无输入。本地任务、工作流、写操作、数据导入和界面切换未结束时继续等待。Runtime 或工作台启动失败本身不阻止安装：启动失败页或已崩溃的渲染进程无需编辑确认；存活 daemon 仍须冻结实际任务和写操作。等待期间保留下载，不关闭服务，不累计失败。界面区分下载、校验、等待空闲和准备重启。

安装前重新核对当前更新来源、完整批准快照和本地文件。daemon 的安装准备门禁冻结写操作及服务器切换、登出，暂停新的任务与调度。存活的共享 Web 再次确认没有编辑或输入活动，中止 Runtime 请求、模型及任务 SSE，禁止新请求，并通过已有受信 IPC 确认；没有工作台的故障启动页无需此确认。随后停止 Bootstrap、Runtime 和 daemon。模型 SSE 已使用 `preClose` 结束连接；任务 SSE 和 MCP 也在 HTTP 等待连接关闭前清理。daemon 完成 Runtime、日志、数据库及锁清理后发送带本次更新编号的 `shutdown-complete`。桌面以 daemon 实际退出和 Runtime 子进程清理完成为安装条件，确认消息缺失、清理失败消息或非零退出码写入诊断，不单独阻止安装；daemon 在请求前已退出时，仍等待残余子进程清理。旧进程或子进程仍存活、清理超时或失败时取消安装。

更新专用 daemon 清理期限为 10 秒，桌面停机预算为 13 秒，保留确认余量；普通退出仍使用原来的期限。Web 确认另有 3 秒上限，停机后的授权与摘要复核共享 20 秒上限。停机阶段开始与完成写入本地日志，便于识别卡住的阶段。停机后使用本次已冻结的 HTTPS Gateway 再次读取公开快照并验证文件；失败则取消本次安装并恢复工作台。不能停机后从渲染层重新获取渠道或身份。后台校验结果同时绑定 SHA512、路径及文件身份，校验期间或校验后发生文件替换即失效；最终仍重新读取文件摘要并检查文件身份及读取期间的变化；不会从本地记录读取下载地址或授权。

macOS 下载 ZIP 后验签，检查新旧应用的真实 TeamIdentifier、Bundle Identifier 和目标真实版本；只有停机后才启动 Squirrel 原生安装准备，等待成功后授权退出并安装。Windows 允许未签名 NSIS 包执行正常自动更新及单次升级复测，不要求 `publisherName`，也不执行 Authenticode 发布者校验；更新来源、批准快照、安装包大小、SHA512、文件身份、空间和权限检查继续生效。Gateway 允许标记为 `unsigned` 的 Windows 包进入批准快照；macOS 仍须正式签名并公证。Windows 自身的安全策略及提权提示继续由系统处理。

`electron-updater` 继续锁定为 6.8.10，`autoDownload=false`、`autoInstallOnAppQuit=false`。自动下载和安装由应用状态机在门禁满足后调用，不依赖普通退出触发安装。原生安装器接管后不承诺可撤回或任意崩溃自动回滚。

Windows 更新使用 NSIS 静默覆盖安装，完成后自动启动新版，不显示安装向导；需要提权时仍由 Windows 显示权限确认。首次安装保留安装向导和目录选择，macOS 沿用 Squirrel 原生替换流程。

Windows 静默更新在替换文件前原子写入安装状态，状态文件位于安装目录旁的 `<安装目录>.clawee-update.json`，避免旧版本卸载时删除。全部应用文件和注册信息写入完成后，安装器才标记完成并拉起客户端。全用户安装由提权后的进程写入状态。安装期间打开客户端会显示等待窗口，完成后继续启动；若等待进程加载的是旧版本，则重新启动新版。等待窗口关闭会取消本次启动，安装失败或超过十分钟会提示重新运行安装包修复。安装等待期间接收到的 Clawee 链接在工作台就绪后继续处理。

桌面日志记录目标版本、安装 PID、安装耗时、`--updated` 启动标记和工作台就绪耗时，便于区分文件复制与 Runtime 初始化。Runtime 异常详情和本地应急反馈支持纵向滚动，导出期间锁定表单并保留取消或失败后的填写内容。模型状态不再拦截整个工作台；未配置、检测中或服务不可用时仍可查看历史、文件、配置、工作流和已授权的企业资源，实际模型执行仍需模型就绪。

macOS 校验解压目录使用 Electron 的 `original-fs` 清理，将 `.asar` 作为真实文件删除，避免普通 `node:fs` 按虚拟目录递归处理、反复重试而使下载状态停留在 100%。回归测试使用真实 Electron 与 ASAR 文件覆盖此行为，不代替真实签名升级验收。

原生安装准备成功后，先授权安装退出并将窗口切换到允许关闭的状态，再调用 `quitAndInstall`。macOS 原生更新器先关闭所有窗口，随后才触发应用的 `before-quit`；不能等到该事件才解除“关闭即隐藏”的拦截，否则安装会超时，后续检查还可能清理 ShipIt 已暂存的应用，导致重启仍为旧版。安装失败恢复工作台时，同时恢复普通窗口关闭行为。

## 状态、失败与恢复边界

主进程在用户数据目录原子写入 `customer-update-state.json`（临时文件、刷盘、重命名，权限 0600）。包身份由 HTTPS Gateway、目标版本、平台、架构、SHA512 组成，**不包含 revision、下载地址或登录会话**。同一包停用再启用或只修改 revision，不能绕过失败暂停；新包仍须重新获取当前更新来源及批准快照。记录只包含编号、原版本、目标版本、包哈希、阶段、时间、尝试次数和错误码，不包含凭据、提示词或用户内容。记录内容损坏或结构不兼容时，自动重命名为同目录的 `customer-update-state.json.corrupt-<随机编号>`，原子重建空记录，再从当前 Gateway 获取授权，不恢复旧的模拟测试或安装请求。文件读取权限、备份或重建失败、持续不可写时仍暂停更新，允许启动工作台。

持久阶段依次为 `ready → preparing → native_requested → awaiting_start → succeeded`，接管前失败转为 `paused`。`preparing` 在冻结之前落盘，防止进程在停机期间终止后重新循环；等待任务或活动门禁时回到 `ready`，不计安装尝试。

| 情况 | 自动行为 |
| --- | --- |
| 任务、工作流、写操作、未保存文件、输入活动 | 保留下载，等待下一空闲窗口 |
| 下载或原生安装准备前的来源复核遇到临时网络错误 | 从 30 秒起指数退避，最长间隔 15 分钟，持续重试；重启保留包的失败计数及下次重试时间；若已停机先恢复工作台，重试仍须重新满足空闲门禁 |
| 下载包损坏 | 只删除对应文件，最多自动重新下载一次；再次损坏暂停 |
| 签名、身份、解压、空间、权限失败 | 停机前暂停，避免打断工作台 |
| 缺少清理确认消息、daemon 异常退出，但相关进程已结束 | 记录诊断并继续安装 |
| 停机或子进程清理超时、清理失败、接管前原生准备失败 | 取消安装、恢复工作台并持久暂停；不再每 30 秒打断 |
| 原生安装请求已发出后报错或退出超时 | 保留 `awaiting_start`，不恢复旧 Runtime、不再次调用安装器；退出后重新打开确认 |
| 重启仍是旧版本、安装过程中进程终止 | 标记未完成并暂停；不盲目再次安装 |

暂停后只有明确点击“重试”才重新授权、校验并恢复自动推进，普通“检查更新”不会解除同包暂停。macOS 原生准备超时或取消后，本次进程不再复用无法判定结果的 Squirrel 请求，须重新打开应用后明确重试；迟到事件不能触发安装。原生请求在控制器及适配器两层保持单飞。

只有实际运行版本等于目标版本、数据迁移结束、daemon 本地启动及共享工作台就绪后，才写入 `succeeded`；NSIS 的 `complete` 只表示文件替换完成，不表示客户端已成功启动。Windows 继续复用安装目录旁的状态文件，并由主进程更新记录补充启动确认。安装等待进程最多重启一次；重启仍是旧版本会显示修复入口，陈旧完成记录也不会引起循环。macOS 使用相同的主进程记录确认启动。成功确认不调用 Gateway 或模型服务，离线和未配置模型不单独构成安装失败。

接管前失败恢复当前工作台；恢复也失败时同时保留安装错误码和恢复错误码。共享工作台显示“已恢复 / 恢复失败 / 自动安装暂停 / 原生结果待确认”，启动恢复页保留重新检测、导出诊断及官方安装包入口。本地日志沿用现有脱敏与诊断策略，不增加默认外传。更新编号贯穿持久记录、桌面停机请求和 daemon 清理确认。

会话位置复用现有导航持久化，提示词草稿按 Gateway、账号、Agent、项目和会话隔离保存在原有 Web 本地存储中，发送后清理对应草稿。文件未保存时禁止安装；草稿写入失败也禁止自动安装。本次不改变配置、Runtime 会话和用户文件位置，不引入不兼容数据库迁移。未来加入不兼容迁移前必须先实现并验证一致性恢复点（SQLite online backup 或离线检查点，包含 WAL），不得复制运行中的数据库主文件作为备份。未经兼容性验证，不自动降级或无条件回滚。

## 客户端单次升级复测

桌面端“设置 → 关于 Clawee → 客户端版本更新 → 升级测试”提供共用入口。输入低于实际运行版本的模拟起始版本，点击“执行一次升级测试”，由当前 HTTPS Gateway 重新读取批准版本，复用正常下载、平台校验、摘要校验、空闲门禁、停机和平台原生安装流程。模拟操作不改写真实应用、安装文件或数据库的版本，实际安装仍以批准包为准；模拟参数只用于本次检查，不作为授权或下载地址来源，也不允许安装低于实际版本的包。

界面不限制操作系统；由现有原生更新能力决定是否可执行。Windows NSIS 支持同版本覆盖复测；macOS Squirrel 的同版本覆盖复测直接返回不支持原因，仍可测试实际更高版本；没有原生更新器的平台或安装包展示原因并禁用操作。不为测试入口改造安装器。Windows 的版本比较仅在本次 electron-updater 检查中临时使用模拟值，无论成功或失败均恢复真实值。

每次点击只授权一次安装。任务忙、未保存文件或输入活动时保留下载并等待，可取消等待；失败或取消后保留记录并停止，不自动重试或跨重启续跑，重新测试必须再次明确点击。原生安装接管后不能取消、重复安装或恢复旧 Runtime。测试结果保存于现有本地更新记录；启动时不恢复模拟版本。同版本复测必须读取区别于安装前快照的本次 NSIS 完成记录，再确认实际版本、本地初始化、daemon 和工作台就绪；记录缺失、未变化或目标不符均不能报告成功。Gateway 离线和模型未配置不单独构成初始化失败。

该入口验证当前客户端的更新流程与真实安装重启，不等同于真实旧版本代码到新版本的兼容性或数据库迁移验证，不能替代发布所需的跨版本实际升级证据。测试使用隔离设备或专用系统用户及合成数据，不操作真实用户数据库。

## 迁移与验证

既有 v1.0.5 包不能通过后台配置获得新的动态渠道能力。首次采用此实现需手动安装新的通用客户端，再验证该版本到后续版本的升级，不覆盖旧正式产物或移动 Tag。

已受旧版 SSE 停机缺陷影响的 **1.0.18**：从官方发布入口下载对应平台的安装包，正常退出旧应用；若无法退出，先导出诊断并确认本地任务已结束，再结束旧进程。macOS 用官方 DMG 将新应用覆盖到原安装位置，Windows 重新运行官方 NSIS 包覆盖安装。保留用户数据目录，不卸载清空配置、会话或数据库；启动后核对实际版本及本地工作台。新代码无法修复尚未安装它的 1.0.18。本机已证实的停机原因不代表其他设备具有相同升级起点或连接状态。

单元及集成测试覆盖版本选择、启停、同版本重新启用、CAS 冲突、元数据损坏、连接切换、登出、离线、任务和编辑门禁及原生安装顺序。修改客户端后运行 `desktop:preflight:local`；完整发布验收仍需真实旧包到新包的安装替换、重启、版本核对以及本地配置、会话和数据保留证据，不能用 fake 安装器测试代替。

新增专项测试使用隔离目录及测试数据库，覆盖失败跨重启持久化、同包 revision 变化、退避和损坏上限、停机确认及退出码、模型与任务 SSE 联合关闭、重复清理、安装单飞、超时及迟到回调、旧版重启、新版本地初始化成功或失败，以及双重恢复错误。发布前仍缺一不可：macOS Intel、Apple Silicon 和 Windows 上的真实旧包到新包升级、跨版本升级、安装进程终止及数据保留证据。先在内部测试 Gateway 和少量设备验证，再复用批准版本与停用能力扩大范围；不建设新的灰度平台。
